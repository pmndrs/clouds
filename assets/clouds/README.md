# Runtime cloud assets

Generated by `node scripts/nubis/convert.mjs` (deterministic, no dependencies, about 3 s) from the
committed subset in `assets/nubis-voxel-clouds/`. Source: Andrew Schneider / Guerrilla Games, see that
folder's `NOTICE.md`. Do not edit by hand.

## Files

| Path | Format | Content |
| --- | --- | --- |
| `<cloud>/nvdf.bin` | rgba8 | R dimensional profile, G detail type (0 wispy, 1 billowy), B density scale, A unused. Cropped. |
| `<cloud>/sdf.bin` | r16 unorm, little-endian | Signed distance in metres, `m = -256 + v * 4352` (pack range -256..4096 m). Negative inside. |
| `<cloud>/cloud.json` | json | dims, voxel size, crop offset, bounds in metres, encodings. |
| `noise/noise.bin` | rgba8 | 128^3 noise with a full mip chain (128, 64, ... 1), mips concatenated. |
| `noise/noise.json` | json | mip offsets and byte sizes, channel meaning, 100 m tiling. |

`<cloud>` is `parkouring` or `stormbird`. Voxel size is **8 m** on every axis (verified, see below).

## Layout and axes

- Texel `(x, y, z)` sits at index `(z * dims[1] + y) * dims[0] + x`: x fastest, then y, then z.
- Source axes are z-up: `x` = map column, `y` = map row, `z` = slice index (0 = bottom).
- The TGAs have a bottom-left origin; rows are kept in file order, so +y is "up" in the source image.
  Top-left files would be flipped by the decoder to the same orientation.
- Grid origin: voxel `(0,0,0)` of the full 512 x 512 x 64 source grid. `cloud.json` `cropOffset` is the
  crop's first voxel in that grid and `boundsMeters.min = cropOffset * 8`.
- **Runtime mapping:** world `(x, y-up, z)` maps to texture `(x, z, y)`. That is, texture x = world x,
  texture y (map row) = world z, texture z (slice) = world y (height).

## Crop and SDF

- Crop = bounds of `profile > 0` plus an 8-voxel (64 m) margin, clamped to the grid.
- The SDF is an exact 3D Euclidean distance transform (Felzenszwalb) of `profile > 0`, computed on the
  **full** grid and then cropped, so values inside the crop are correct. Distance is voxel-centre to
  nearest opposite-state centre, minus half a voxel (surface lies between them).
- Encoding rounds down, so a decoded distance never overshoots the true one.
- Outside the crop the runtime should treat space as far and empty. At the crop faces the stored
  distance is at least about the margin (64 m) except where the crop meets the grid floor/ceiling:
  Stormbird touches z = 0 and the cloud is simply cut off there.
- Max distance clamps at 4096 m (the encoding range); a 512-voxel grid at 8 m never exceeds it.

## Voxel-size check (vs the pack's 8-bit `field_data` SDF, |d| < 200 m, about 0.7 M samples per cloud)

`convert.mjs` runs it when the full pack is present (`--pack <dir>`, `--no-check` skips). At 8 m:
median |diff| 4.4 m (Parkouring) and 4.9 m (Stormbird), p90 10-12 m, sign mismatch 0 and 529 of
about 0.55 M voxels beyond one 17 m quantum. The 529 are all at grid z = 0..1, where the pack's own SDF
is flat zero at the floor. 4, 6, 10, 12 and 16 m all fit worse (median 21-110 m).

## Hero assets: `fine.nvdb` (additive, P8 spec)

The `-fine` heroes (`disney-fine`, `heroes/sim-cumulus-fine`, `heroes/sim-congestus-fine`) carry `fine.nvdb`: a NanoVDB Fp8 fog grid `profile` (codec NONE, values k/255) of the
dimensional profile at 4 m (2 m for `local/disney-2m`), (the float `fine.vdb` it was built from is dropped; rebuild it with the recipe). `cloud.json` has a `fine`
block (`ratio`, `dims`, `shellMeters`, `bytes`, `leaves`, `indexAxes`). Loaders that do not know `fine` ignore it. The coarse
`nvdf.bin`/`sdf.bin` of these assets are the 2x2x2 reduction of the fine profile (mean, floored at 1/255 where any fine voxel is set),
so they differ from the shipped 8 m `disney` and `heroes/sim-*`, which stay unchanged for the existing demos. The sim heroes were re-simmed at 4 m, so they are a different realisation; `sim-congestus-fine` is 5.15 MB coarse, over the usual 4 MB cap, which is accepted for this showcase asset. Recipe and checks: `scripts/vdb/README.md`.

## Artist pipeline: Houdini VDB to NVDF

`scripts/vdb/vdb_to_nvdf.py` (run with hython, see `scripts/vdb/README.md`) writes this same format from VDBs:
`--mode pack` (Nubis NVDF VDBs; reproduces the TGA-derived `parkouring` and `stormbird` byte for byte apart from
two 1/255 differences), `--mode fog` (artist density VDB; profile = saturate(-sdf / depth)^gamma, default depth
96 m), `--mode sdf` (level set). VDB axes map as texture x = VDB X, texture y = VDB Z, texture z = VDB Y. The
`houdini-test/` cloud is a noise-displaced sphere cluster made by `scripts/vdb/make_test_cloud.py` and converted
with `--mode fog` (8 m voxels, from a 4 m VDB).
