## The minifier
`scripts/wgsl-minify.mjs`, an esbuild `onLoad` plugin used by `build-release.mjs`. It rewrites only template literals tagged `/* wgsl */` (nested templates inside their `${}` inherit), on the TS source before esbuild. It removes `//` and `/* */` comments (nesting-aware), collapses whitespace, and drops spaces around `{ } ( ) [ ] ; , : =`. Identifiers, operators (`+ - * / & | < >`), numbers and interpolations are untouched; a space beside an interpolation is kept. It throws on a backslash in a WGSL part, an unterminated comment, or a line comment running into `${}`. Sources stay readable. Untagged templates are left as written, so new WGSL needs the `/* wgsl */` tag (all existing ones have it).

A/B (flagship ground/inside/backlit/shadow, source vs minified dist): differences are only the HUD text (top-left) and temporal-jitter noise at the level of two runs of the identical build. Ground: 162 px over threshold between two identical-dist reruns, 330-790 between builds; inside/backlit/shadow: 0 px outside the HUD. GPU pass times unchanged.

## Proposals (not done; the core now has about 9.6 KB gzip of headroom)
1. Split `generate/shaders.ts`: the sky layer and shadow map import it for shared functions (BILLOW_WGSL), and 28.7 KB raw is the largest single module in core. Separate the shared field functions from the volume-generation passes; est. -8 to -12 KB raw (about -3 KB gzip).
2. Lazy-load the shadow map (shadow-map.ts plus its WGSL, ~10 KB raw) behind a dynamic `import()` when enabled; needs an async init point in `runtime.ts`.
3. Moving the sky-layer weather bake into `/generate` is not worth it now (~3 KB gzip, forces a dynamic import in the sky layer).
4. Squeezing spaces around `< > + - * /` or a renaming WGSL minifier: gzip already absorbs most of it; not recommended.
