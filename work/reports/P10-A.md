# P10-A Cloud shadow map
Status: ready for review
Changed: packages/runtime/src/shadow-map.ts (new), packages/runtime/src/shaders/shadow-map.wgsl.ts (new), packages/runtime/src/runtime.ts, packages/runtime/src/shaders/composite.wgsl.ts, packages/runtime/src/index.ts, packages/runtime/src/shaders/sky-layer.wgsl.ts (refactor, below), examples/lab/open-water/main.ts and cloudscape-gen/main.ts (debug query params only)
Design: world-anchored, toroidal map on the cloud shell's base plane. Texel = optical depth (tau) of the sun ray up through the shell. Voxel box = light grid read at the box entry (same value the old composite path read); everything else = the sky layer's cheap field (`SKY_FIELD_WGSL` `skyModel`, the field its own sun samples integrate), fixed 48-step midpoint march with the field's skip distances and coverage mips. Lookup: `q = p.xz + sun.xz (planeY - p.y)/sun.y`, bilinear. Near cascade 8 km at 8 m texels, far 64 km at 64 m (1024^2 r32float each, 8 MB total), blended over the near window's outer 16 texels. A cascade follows the camera's foot point (projected along the sun) in 64-texel snaps, so nothing moves: a texel's world cell never changes, only which cells the window spans.
Refresh: 1/24 of the rows per frame (double rate for the first fill and on a sun jump), only while stale. Invalidated by: sun moving the plane point > 4 m at the shell top, grid rebuild swap, weather re-bake, sky densityScale/curvature, extinction, light density scale, box move, window recentre. Until the first full sweep lands the composite uses the old light-grid shadow, so there is no partial map on screen. `settings.enabled = false` returns to the old path (A/B).
Runtime interface: `runtime.shadowMap` (`textures`, `paramsBuffer`, `settings`, `info`, `bindGroupLayoutEntries/bindGroupEntries`), and `cloudShadowMapWgsl(group, binding)` which gives adapters `cloudShadowTau(p)` / `cloudShadowValid()` (uniform at binding, near r32float at +1, far at +2; textureLoad only). Exported from the package index. Composite binding 14..16.
Refactor: `sky-layer.wgsl.ts` split `SKY_PARAMS_WGSL` into `SKY_STRUCT_WGSL` (struct + Bayer, no `frame`) and `SKY_SCENE_END_WGSL`; `SKY_PARAMS_WGSL` is their concatenation, so the sky trace and the dome are byte-identical. The field functions (`SKY_FIELD_WGSL`) are reused, not copied.

## Fix (orchestrator review: grey ghosts over distant sky-layer cloud)
Root cause: `composite.wgsl.ts` multiplied the shadow into the voxel alpha before `mergeSky`. The merge computes `front.rgb + front.a * (voxel.rgb + voxel.a * back.rgb)`, so the shadowed `voxel.a` also scaled the sky layer's back-cloud radiance and made it translucent. Where sky cloud sat over a shadowed surface the cloud was darkened and the ground showed through as grey shapes.
Fix: the shadow factor is now applied to the final alpha after the sky merge (`result.a *= cloudShadow(...)`), so it darkens only the surface term (scene * a) and never a cloud's own colour. Identical to before when the sky layer is off.
Verified: re-captured cloudscape, cloudscape-off, open-water, open-water-off, flagship in work/captures/P10-A/; cloudscape/above.jpg band is solid white cloud again, shadows still visible on the ground in gaps. `pnpm check` exit status checked after the fix (see below). Result: exit 0.
