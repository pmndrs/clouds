# P1-09 Art pass: inner glow, dark edges and undersides
Status: ready for review
Changed: packages/runtime/src/{runtime.ts,shaders/march.wgsl.ts,shaders/frame.wgsl.ts (uniform 192->224 B),shaders/density.wgsl.ts (wispyBias, needed for item 4)}; examples/lab/flagship/{bookmarks.ts (frontlit, sun ~32 deg, camera on the sun azimuth), main.ts (report adds sunElevation/sunAzimuth)}.
Key finding: with the sun behind the camera the direct term (HG at cos -0.85) contributes ~0; the look is ms + ambient. The old flat beige body came from ambient (ground-light blend). Pure P-gating of the direct light did nothing visible.
New settings (Nubis-neutral = 0 / 0.3 / 1 for msStrength, ambientStrength):
- edgeDarkening (1): radiance of rays that stay shallow in the SDF (silhouettes/grazing) is scaled toward 0.08, weighted by "sun behind viewer".
- glowFront (1): applies the sun-facing extinction relaxation also front-lit, so interior bulges stay bright.
- glowBoost (12): ms x (1 + glowBoost*sunRelax) when looking toward the sun.
- ambientSkyBias (0.9): sky-above share at the cloud base (Nubis 0.3) -> blue-grey undersides. ambientExtinction 0.3.
- wispyBias (1): detail type scaled by 1-bias*(1-h)^2 (wispier near the base); 0 = unchanged density.
- Also default msStrength 1.4. All colours remain sky-derived.
Verified:
- parity: `node scripts/gpu/capture.mjs --serve --page runtime-tests/density/ --out work/captures/scratch/p109-parity` -> pass true (formula max 2.8e-7, end-to-end 4.3e-3). The page embeds its own WGSL copy, so it does not exercise wispyBias; the runtime shader defaults are not neutral by design.

- captures: work/captures/P1-09/{parkouring,stormbird}-{ground,frontlit,backlit,edge}.jpg = Tidewater | P1-07 baseline | P1-09 (cropped, 800x450 tiles); capture-*.json.
Cost (march near+far ms at 1920x1080, headless): baseline vs P1-09: parkouring ground 0.71/0.43, frontlit 1.26/0.56, backlit 0.92/0.51, edge 1.31/0.53; stormbird 1.19/0.88, 1.17/0.94, 0.84/0.55, 1.44/0.70. Not slower (within +0.3 ms); the drop is mostly the brighter ms clipping to opaque earlier plus noise (baseline ran in a different session); do not read it as a speed-up.
Honest look assessment:
- Dark edges front-lit: PARTIAL. Stormbird frontlit now has bright cauliflower tops and a dark/grey base and interior clefts. The outer silhouette rim is still bright white (tone-map saturation); edges are only slightly greyer. Reads as dark underside/clefts rather than dark rims.
- Backlit glow: Stormbird YES (bright body, luminous blue-lit pockets, silver rim). Parkouring PARTIAL: whiter body than before but still one dark core; the cloud is small and thin.
- Blue-grey undersides: PARTIAL-YES on Stormbird edge (blue-grey shadowed lobes); front-lit undersides are grey/charcoal, not Tidewater's teal.
- Wispier undersides: subtle; visible mostly as softer fringes at the base. Tidewater-like wisps need asset/profile work.
- Overall the clouds are brighter/whiter than before (bulges near clipping); consider lowering exposure or msStrength if that is too much.
Open issues: the Parkouring dark core in frontlit is a hard blob (low profile cavity); edge darkening uses SDF depth, so it also greys small thin clouds. thresholds EDGE_DEPTH 70 m / EDGE_FLOOR 0.08 are shader constants. frontlit bookmark framing uses 1.15*r distance.

## Orchestrator review
The defaults above left front-lit undersides charcoal, reading like smoke. I swept `ambientExtinction` and
`edgeDarkening` with URL overrides (`work/captures/P1-09/orchestrator-ambient-sweep.jpg`) and chose
**ambientExtinction 0.08, edgeDarkening 0.5**: bright tops, blue-grey bases, soft dark clefts. Accepted with
those defaults. The remaining gap is wispier undersides, carried to the P3 art pass with generated cloudscapes.
