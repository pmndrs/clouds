Design notes / deviations:
- Storage format is rgba16float, not rg16float: rg16float write-only storage is not a core WebGPU storage format (needs `texture-formats-tier1`). rgba16float is core, filterable, only .rg used (x = sun, y = up). Memory is <0.2 MB for Parkouring. If tier1 is later required-feature-gated, switching is one constant.
- Ping-pong: textures[0/1]; scheduler.front says which is complete. Consumers prebuild two bind groups via `bindGroupLayoutEntries/bindGroupEntries(binding, index)` and pick `frontIndex` each frame. `lightGridWgsl(group, binding)` puts the texture at `binding` and a filtering sampler at `binding + 1`; it needs volumeWgsl(g) in the same module. Swap happens at record time of the final slice; passes encoded after `encode()` in the same encoder see the finished grid.
- Per voxel: midpoint march from the voxel centre to the box exit (sun and straight up), step = max(min grid cell size (~16 m), exit/128), summing sampleModeling(p,0).r * .b * densityScale * step. `densityScale` is the encode param (multiplier); the raw NVDF B channel is used without the sampler's pow(.,4). The march should apply exp(-sigma * sum).
- Scheduling: first-ever build all slices in one frame; later builds 8 passes of floor(k*gz/8)..floor((k+1)*gz/8). Rebuild starts (when idle) if sun is >0.5 deg from the front's sun, densityScale changed, or `invalidate()` was called (volume edit). Mid-build restart also on >0.5 deg from the build's latched sun or a density-scale change. The same `frameIndex` encoded twice does not advance. No idle cycling, so a static sun costs zero.
- Parameter uniforms use a ring of 8 buffers so several encodes per submit (tests) stay correct.
