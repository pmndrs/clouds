Clouds are one volumetric layer: base 4000 m, thickness 5200 m (SkyProClouds PRESET "Partly cloudy"). Even from 300 m the layer is still overhead, so (d) shows sparse cumulus above a sea horizon, not a view across the tops. No higher reachable surface exists (boat is at sea level); the free camera could go higher but was not used.
Reproduce:
1. `cd /Users/dex/Developer/tidewater && npm ci && npx vite --host 127.0.0.1 --port 5189` (dev server in background; first load compiles shaders, a few minutes cold, seconds once cached).
2. From the worktree: `node work/captures/P0-04/drive.mjs [--only a,b,c,d] [--settle 12000] [--headed]`. It reuses `scripts/gpu/cdp.mjs`, waits for `window.__app.fps > 0`, clicks `__ui.startEl` ("Click to explore") and `.gm-guide-skip`, then per view runs `__ui.setPhotoMode(true)`, sets `app.settings.timeOfDay` + `app.updateSun()`, `app.setFreeCam(true)`, `app.fly.setPose(pos, yaw, pitch)`, waits 12 s for the temporal cloud history to converge, and screenshots. `views.json` holds the exact values used.
Control surface found: window globals `__app` (App), `__ui`, `__view(name)` / `__views` (named poses in src/core/DebugViews.js), `__pose()` prints the current pose; settings panel (H) exposes time, cloud cover, cirrus, FOV; URL options `?fly`, `?noClouds`.
Open issues:
- Tidewater composites the clouds with its own atmosphere, haze, bloom and auto exposure, so brightness comparisons are only roughly like-for-like; compare shape, edge softness, lighting gradients and distance fade.
- Sun azimuth differs per view (timeOfDay moves it); (c) is aimed at it by computation, not by a named bookmark.
