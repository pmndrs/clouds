Design:
- Dome: octahedral rgba16f 256² (`createCloudRuntime(..., { domeSize })`), rgb premultiplied radiance in the sky's exposure units, a = T. `runtime.dome` = { texture, view, size, referencePoint, refreshFrames, settings }. Settings (live): enabled (default true), referencePoint (null = camera x/z at groundHeight 0), densityScale 0.6, maxSteps 96, stepMin 8 m, stepRel 0.03, maxDistance 12 km. Set `dome.settings.enabled = false` when nothing reflects clouds.
- Density = profile * S (cRenderDome, no up-rez) * densityScale; sun in-line samples are the same cheap density; SDF-skipping march; the lighting is the march's, factored into shaders/lighting.wgsl.ts (`cloudInScatter`, `cloudEdgeFactor`, `cloudPhase`, shared by march and dome). No aerial perspective in the dome (it is camera-frustum based): haze belongs on the reflecting surface.
- Refresh: one thread per 4x4 block shades the texel its Bayer slot picks, slot = frame % 16, so 16 frames cover every texel once. Untouched texels start as (0,0,0,1).
- WGSL: `cloudDomeWgsl(group, binding)` declares the texture and defines `cloudDomeSample(dir) -> vec4` (octahedral decode + manual bilinear with seam mirroring via textureLoad; no sampler needed; below-horizon dirs read (0,0,0,1) because they are never lit). Blend as `env * a + rgb`. Also `DOME_OCT_WGSL` (domeOctEncode/Decode). TS: `domeDirectionToUv`, `domeUvToDirection`, `domeTexelDirection`, `domeDirectionToTexel`, `defaultDomeSettings`.
Measures:
- Dome GPU: 0.054-0.077 ms/frame at 256² (limit 0.15) [GpuTimer pass `dome`]; 2 slots/frame boost frames cost ~0.12.
- Sun change (+2.5 h of sky time; test page, capture.json sunTest): frame time max 16.8 ms vs 16.7 steady (no stall; vsync-bound). Dome error vs the converged result falls to the jitter floor (0.057 relative radiance) by frame 15-16 after the change. Without help it took ~24 (8 frames for the light grid bake + 16 refresh), so when the light-grid swap completes the dome shades 2 slots/frame for 8 frames.
- Direction check: ground bookmark, dome reference (-270, 0, 460), cloud box centre (0, 704, 0): expected az 30.4 deg (compass, N = -Z, E = +X), el 53.2 deg; the panorama shows the cloud centred on the V (camera view) marker at az ~30, and the mask spans az -9..58, el 38..70, inside the box's projected range az -47..82, el 28..81. Edge bookmark (camera elsewhere): cloud moves to az -54..-14 (expected centre -29.6, el 42.7), inside the box range. I reasoned from the placement: camera at +Z/-X of the cloud looks toward -Z/+X, so north-east, which is where the cloud is.
Also folded in (orchestrator request):
1. `setVolume(asset | GpuCloudVolume)`: a GpuCloudVolume (has `extentMeters`) is used as is and never destroyed by the runtime; uploaded assets are still owned/destroyed. Tested with `?volume=gpu`.
2. `'ultra'` quality: near 0.5x, far 0.75x, split 240 m, 1024 steps, cutoff 0.005. `CloudQuality` gains 'ultra' (any exhaustive Record<CloudQuality,..> in other code needs an entry). high/medium/low unchanged.
3. `CloudFrame.lighting = { kind: 'uniform', sunRadiance, ambientTop, ambientBottom }` (new exported `CloudUniformLighting`); `CloudFrame.atmosphere` is now optional (required only without `lighting`). Uniform mode writes the sky-light buffer from the values (no sky-light pass), uses a march variant without the atmosphere group (`marchWgsl('uniform')`, built on first use) and has no aerial perspective. Tested with `?lighting=uniform`.
Open issues:
- Dome density 0.6 is an eyeballed match to the up-rezzed look; tune with the ocean.
- Octahedral map is one texel per direction cell: grazing reflections on large water are bilinear-smooth; a larger `domeSize` is the lever.
- The reference point follows the camera x/z, so a fast camera makes the unrefreshed 15/16 stale for up to 16 frames (invisible at the cloud's range).
