Measures (5000 points on Parkouring: 1000 each deep / near-surface / empty-inside-box / outside-box / near-camera HF; wind on half; 1737 non-zero, 913 with hfDetails; mip forced to 0):
- Formula parity (CPU formula fed the GPU's own filtered NVDF and noise samples): max 2.8e-7, p99 6.0e-8, mean 6.5e-9. PASS (gate 1e-3).
- End to end vs exact-weight CPU trilinear: max 4.3e-3, p99 5.0e-4, mean 5.7e-5. Strict 1e-3 gate FAILS; cause below.
- End to end vs CPU using 8-bit fixed-point filter weights: max 2.5e-3, p99 1.7e-4, mean 2.6e-5.
- Outside box: exactly 0 on all 1000 points.
Why the strict 1e-3 end-to-end gate fails (not a density bug):
- Metal's texture unit quantizes the fractional filter weights to 1/256. NVDF filter error alone: max 3.3e-3 (about 0.85/255) with exact weights, 1.3e-4 with weights rounded to k/256. Steps 16/32/64/128/512 fit worse; 256 is clearly best. Noise filter error: max 9.9e-4 exact, 8.5e-4 / p99 1.2e-4 with 256 steps.
- Density amplifies tiny input errors near the cloud edge: erosion divides by (1 - noise) and then `pow(d, 0.3..0.6)` has slope ~0.6*d^-0.4, which is large for small d. Worst point (nearHF, density 0.06) is a 6e-5 NVDF residual amplified to 2.5e-3.
- The formula port itself matches to float rounding, so the mismatch is hardware filtering, not either implementation.
Proposed tolerance: gate formula parity at 1e-3 (hard) and end to end at 5e-3 absolute (about 1.3 LSB of rgba8). The page's `pass` is both. Do not tighten end to end below ~3e-3 on Apple GPUs.
Deviations / notes:
- CPU `saturate` maps NaN to 0 like the GPU (valueErosion gives 0/0 when profile == noise == 1); Math.min/max would have propagated NaN.
- The CPU reference is mip 0 only and throws if the requested noise mip is > 0. The NVDF has no mips in P1.
- `sampleTrilinear` has an optional `weightSteps` to emulate fixed-point weights (diagnostic only; default exact).
- The page finds DENSITY_WGSL with `import.meta.glob`, so it still builds if the file is absent (falls back to the stub and says so).
Open issues: the end-to-end numbers are Apple/Metal specific; other GPUs may be tighter or looser. Re-run there if it matters.
