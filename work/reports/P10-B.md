# P10-B Cloud shadows in three materials
Status: ready for review
Changed: packages/three/src/{cloud-shadow.ts (new),clouds.ts}, packages/runtime/src/{runtime.ts,shadow-map.ts} (see Open issues), packages/react/src/{index.tsx,props.ts}, examples/lab/{onsen,plains-flight,three-adapter,open-water}/main.ts, examples/lab/scenes/ocean/index.ts (receiveShadow), docs/guide/api.mdx
Design (choice documented in api.mdx "Cloud shadows"): the cloud shadow goes through the sun light, not the material. `clouds.applyShadow(sun.light)` sets `light.shadow.shadowNode` to `clouds.shadow()` (multiplied with a shadowNode already there, so the terrain heightfield shadow and the cloud shadow multiply), `light.castShadow`, `renderer.shadowMap.enabled`, and `settings.compositeShadow = 0` (no double shadow). three then multiplies it into that light's colour for `receiveShadow` meshes: direct sun only, sky/IBL/ambient untouched. `clouds.shadow(positionNode?)` is the raw TSL float (1 lit) for materials that mix their own lighting. `removeShadow(light)` undoes it; React `<Clouds shadowLight={light}>`.
How: the runtime's two r32float cascades are copied (copyTextureToTexture, only on frames a refresh slice ran) into two three StorageTextures; the TSL node ports `cloudShadowTau` (toroidal bilinear load, cascade blend) and the composite's tau-to-light curve. Uniforms come from a new `shadowMap.params` CPU mirror. Returns 1 until `info.valid`.
Verified:
- `pnpm check` -> exit 0 (213 tests). `node scripts/check-packed-consumer.mjs` -> PACKED CONSUMER OK. `node scripts/check-docs.mjs` -> clean.
- captures: work/captures/P10-B/ (`<page>-cs1` = node, `<page>-cs0` = `?cloudshadow=0` composite path)
  - plains-cs1/t0,t25 vs plains-cs0: t25 shows crisp cloud shadows on the fields (sunlit patches dimmed, ambient kept); t0 looks at the sky (2 m altitude), so it carries no shadow. Shadows move because the streamed clouds move.
  - adapter-cs1/shadow (`objects=1`): voxel-only cloud, big soft shadow on the ground, same footprint as cs0, lighter because ambient is not dimmed.
  - open-water-cs1/{horizon,cruise}: no dark band on the far reflections any more (cs0 has one); the direct-sun glint is dimmed only under clouds. Subtle by nature (reflection dominates).
  - onsen-cs1/{vantage,valley} (`skylayer=1`): terrain keeps its heightfield shadows; cloud shadows multiply on top.
Measures: cost = 2 x 4 MB texture copy on refresh frames only (about 24 per sweep, then none while the sun and clouds are static) plus the per-fragment lookup (8 loads) only in receiving materials; not separately GPU-timed (the copy is outside the timer's passes); the shadow map pass itself is unchanged (0.2-0.4 ms, P10-A). The renderer-agnostic test still passes.

- The lookup uses the map's sun (lags the live sun until it moves 4 m on the shell), so a surface can be off by up to about 4 m.
- Surfaces above the shell base are over-shadowed (P10-A limitation). Materials without `receiveShadow` get no cloud shadow once `compositeShadow` is 0.
- `applyShadow` must run after anything that installs its own `light.shadow.shadowNode` (terrain does it in `createTerrain`); the terrain/ocean scene modules needed no change except `ocean.mesh.receiveShadow = true`.
- Pages: `?cloudshadow=0` switches back to the composite path.
