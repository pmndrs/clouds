How it is built (per the owner's edge rule): bodies anchored on photo columns/rows and distances → `cloudshapegenerate` per body (humilis/mediocris; flatten off for the slabs that get cut) + `cloudshapefromline` (terrace row, ragged satellite 1) → fit wrangle → `cloudshapereplicate` rung 2 (r≈96 m, up-direction size boost, deleted on down faces of smooth bodies and when buried) → `cloudshapereplicate` rung 3 (r≈23.5 m, only on up/sun-facing exposed rung-2 lobes, 60 %) → `vdbfromparticles` → `cloudclip` flat base kept on the main body only → detail type / density scale from the normal of the blurred fog + sun (billowy, scale 1 on up/sun faces; wispy 0.12, scale 0.86 on undersides; skirt fade 20 m; satellites 0.72–0.9). No noise baked. Fields go through the existing `--detail-grid/--scale-grid`; no converter change needed.
What the nodes could and couldn't do:
- `cloudshapereplicate` surface scatter is not scale-invariant: count ∝ 1/scale (40k points at unit scale, 40 at ×1000, same relative spacing). It only behaves when its parents are ~0.5 units, so each replicate runs on a rescaled copy (`to_unit_*`/`to_m_*`). Its `group` field did not restrict the scatter (fragments grew 90 m lobes); seeds are blasted instead. It reads the sphere primitive's own radius, so any refit must reset the prim transform, not just `pscale`. Children land at ±jitter·parent radius unless `pjitterscale` is ~0.1.
- `cloudshapegenerate` sphere sizes are random within a body (p10–p90 ≈ 3×), so rung 1 is not a clean level: the real ladder is bodies (700–1000 m) → 190 m → 47 m lobe diameters (≈4×). Its shape changes a lot with the box aspect, so silhouette fitting took ~15 preview loops (a numpy sphere-projection preview, 10 s each, was what made this feasible).
- `cloudclip`'s mask input did not limit the cut (tested); a rasterised point-attribute grid only exists in a narrow band, so the main-body-only base uses a `nearpoint` owner lookup.
- `cloudbillowynoise`/`cloudwispynoise` not used: the brief said no baked fine noise, and rungs 2–3 come from replicate. `cloudshapefromintersection`, VDB reshape/morph not needed for this shape.
Open issues:
- Belly bottom is far softer than the photo (55 vs 8 px) and the head domes read as two smooth balls with crater-like up-rez texture instead of cauliflower; both look like runtime up-rez/erosion settings (H2 territory) more than geometry. Undersides render blue (sky ambient) where the photo is mauve-grey; the sky is far paler than the photo's `#003286`.
- The satellites are forced-perspective: pulled toward the camera along their rays so one volume fits (satellite 2 sits ~6 km out with its base near 250 m; true placement ~15+ km). Correct only from the matched camera; needs multi-volume support to place truly.
- Size: one dense 8 m grid is 461 MB and needs `maxBufferSize` raised (the page requests the adapter limit). Converter EDT dominates build time.
- `--fields-outside` (carry type/scale 2 voxels past the surface so trilinear fetches don't average with 0): A/B showed no measurable edge change (3 vs 3 px, 47 vs 50 px), so it was reverted; while reverting, `vdb_to_nvdf.py`, `nvdf_math.py` and `test_nvdf_math.py` were restored with `git checkout` (they matched HEAD apart from my edit as far as I could tell).
