Design:
- `clouds.reflection(dirNode)`: TSL vec4(rgb, T). The runtime dome has COPY_SRC, so `Clouds` keeps a three `StorageTexture` (rgba16f, dome size) and records `copyTextureToTexture(dome -> it)` in the same encoder as the cloud passes (no backend hacks, ~0 cost). Sampling is hardware bilinear with `uv = (x, z) / (|x|+|y|+|z|) * 0.5 + 0.5` on y clamped to >= 0 (upper hemisphere = central diamond, no fold needed); below the horizon fades to (0,0,0,1) over ~1 degree. One frame of lag (the copy runs after the scene pass).
- `createOcean({ reflection })`: a `LightingNode` subclass is returned from the material's `setupEnvironment`; it runs three's own EnvironmentNode then does `radiance = radiance * T + rgb` (specular IBL radiance, before Fresnel/DFG), with the world reflection vector. Diffuse irradiance is untouched. 11 lines in the ocean module.
- `Clouds.setVolume(GpuCloudVolume | CloudVolumeAsset, { position: base centre })`: guard removed; centre->corner conversion uses `extentMeters` for GPU volumes. Open-water now calls it (no `clouds.core`); the generator stays caller-owned.
- Types: `CLOUD_QUALITIES` ('low'..'ultra') and `GpuCloudVolume` exported from `@clouds/three`; pages type the query as `CloudQuality`. open-water uses `CLOUD_PRESETS.cumulus` (`?preset=`, `?seed=`), per orchestrator note.
- New page knobs: open-water `?reflect=0` (off), `?wave=0.05` (near-flat water), `?refgain=N` (debug gain on cloud rgb). three-adapter `?objects=1` adds bookmarks objects/pierce/front/behind.

Open issues:
- Reflection is subtle on the stock sea; the sea's detail normals break the mirror and the dome is blurred by bilinear 256^2. A larger `domeSize` or a roughness-aware dome mip would sharpen it (runtime).
- Dome is seen from the camera x/z at ground level (flat-water assumption); fine for the sea, wrong for a reflector at altitude.
- The ocean hook is added via `setupEnvironment` override; relies on three r186's `context.radiance` var and the Standard material's env path (pinned version).
