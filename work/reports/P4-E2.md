# P4-E2 Rebuild the tower hero cloud as towering cumulus
Status: ready for review
Changed: scripts/vdb/authoring/build_heroes.py (tower_spheres + tower recipe), scripts/vdb/authoring/README.md (knobs + tower section), assets/clouds/heroes/tower/ (rebuilt, same path), work/captures/P4-E2/ (ground/edge/backlit jpg, capture.json, side-by-side.jpg).
Verified:
- `hython build_heroes.py tower` cooks and converts (`--mode fog`, 8 m voxels, `--iso 0.3`), 3.58 MiB (under 4 MB) at scale 1; about 690 x 930 x 580 m.
- Flagship `?cloud=heroes/tower` captured at ground, edge, backlit (exit 0). side-by-side.jpg: left old P4-E tower, right new, rows ground/edge/backlit.
Look: broad foot, six stacked layers of domed turrets at different heights, mid-height about as wide as the base, notches between cells, slight +x shear, two crowning domes of different height, bright tops and a darker, bluish interior in backlit. No more narrow stalk or mushroom head. Cloud SOP secondary bumps + 3 noise passes give lobed edges.
Open issues:
- Base is still ragged/wispy in the edge view (noise erodes the foot); a denser or flatter foot would read more like a flat cumulus base.
- Cells are fairly smooth domes; detail finer than about 25 m is not representable at 8 m voxels.
- Asset path unchanged (assets/clouds/heroes/tower), so the onsen demo needs no change; its size/bounds changed (see cloud.json), so any placement scale tuned to the old tower should be rechecked.

## Orchestrator review
Accepted as an improvement: the plume stalk is gone and the body is broad and stacked. It still reads as a pile of
soft spheres rather than cauliflower cumulus. Guerrilla's richness comes from fluid-sim authoring (Nubis³
s63–64); scripted Cloud SOP recipes have a ceiling. If authored hero quality matters for the release, the next
step is a Houdini pyro or cloud sim recipe, which is a user decision because it involves heavier artist workflow.
