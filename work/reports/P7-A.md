Design:
- `<Clouds volume position quality settings sky haze lighting planetCenter onLoad>`: any other prop is a `CloudSettings` key (`<Clouds densityScale={0.02} />`). Sky is `useSky()` unless `sky={false}` (uniform lighting) or a Sky is passed. Children mount once the instance exists; `useClouds()` returns the `@clouds/three` `Clouds` (settings, timings, isReady, reflection(dir), core).
- Instance: one per (renderer, sky, planetCenter), created after `renderer.init()`, disposed in the same effect's cleanup (state-driven disposal leaked the first StrictMode instance). Quality, settings, lighting, volume and noise are effects on the live instance; volume/noise work is serialised in a promise queue. Removing a settings prop restores the value the instance was created with.
- Suspense: URL volume and noise use `use()` on a module cache (`preloadClouds`, `clearCloudsCache`); a failed load is evicted so a remount retries. Swapping the volume URL suspends the nearest boundary (wrap in `startTransition` to keep the old frame).
- Pipeline: `useRenderPipeline()` only guarantees the pipeline and scene pass; the clouds node is installed in an effect around the pipeline's current `outputNode` (plain scene pass -> its texture node; otherwise the existing colour, e.g. `<AutoHaze />`'s), and `outputNode` is handed back as found on cleanup. Works whichever of `<AutoHaze />` and `<Clouds>` comes first in the tree. The scene pass behind a hazed node is not reachable from the node, so it is taken from the other `useRenderPipeline` instance's store entry (one scene render; falls back to our own pass with a console warning, rendering the scene twice).
- `<Cloudscape preset seed dims voxelSize baseHeight follow jobsPerFrame>`: `createStreamingCloudscape` driven in `useFrame`; standalone it wraps its own `<Clouds>`, nested it drives the parent. Volumes stay streamer-owned; on unmount or preset change the clouds are pointed at a tiny empty volume (or the new streamer's first window) before the old streamer is destroyed.
Open issues:
- Adapter bug (packages/three, not touched): `Clouds.dispose()` does not call `this.timer.dispose()`, leaking 4 buffers (timestamp query set, resolve and 3 readbacks) per instance. `<Clouds>` works around it by calling the private `timer.dispose()` (marked TODO); remove it once the adapter frees the timer.
- Put `<Clouds>` and `<AutoHaze />` in the same `<Sky>`. If another `useRenderPipeline` user replaces `outputNode` after `<Clouds>` mounted, the clouds are dropped (R3F gives no pipeline composition order).
- Changing `position` re-uploads a URL volume (the runtime has no move-only call); `planetCenter` and `sky` changes recreate the instance (reload of the volume).
- The demo's `CameraRig` registers window listeners that are never removed (page-lifetime, same as the other pages). `?stress=1` needs `--settle 1500` in the capture so the run finishes; read `shots[0].report.stress` and `.gpu`.
