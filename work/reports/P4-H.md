How it works:
- Parser: vendored `parseVdb` plus changes listed in `vendor/vdb-web-tools/NOTICE`. Needed and not in upstream: Blosc lz4 decoder (`blosc.ts`; the pack VDBs, cloud.0001 and Houdini's default are Blosc), constant tiles kept (the pack's detail_type/density_scale are mostly active tiles; level-set interiors are -background tiles), OpenVDB's inactive-value defaults (level sets), and the pre-222 leaf layout (bunny_cloud). `select` option lets a first pass list grids without decoding and the second decode only what is used (the pack's 16.7 M voxel `sdf` grid is never decoded; it only gives the crop clamp bounds).
- Resampling: scatter of leaf voxels and box-weighted tiles straight into the target lattice with the same tent filter as `nvdf_math.resample_matrix`; no dense source array (bunny_cloud's source box is 143 M voxels). Axes: texture x = VDB X, map row = VDB Z, slice = VDB Y (y-up), identical to the Python converter and `assets/clouds/README.md`.
- Channels: pack mode copies the grids (profile quantised, crop = occupied bounds + 8 voxels clamped to the pack grid); fog/sdf modes use `PACK_FIT` (ported 1:1 from `nvdf_math.py`) with depth from the mask EDT (`signedDistanceCpu`). SDF: `createEmptyCloudVolume` + `createSdfRebuilder({ rounds: 2 })` (P4-C), so the stored SDF is conservative as for stamped clouds.
- Page: `?url=` (also `/@fs/...`), drag and drop, file picker; overlay with grid table, mode, dims, timings and frame/GPU ms; bookmarks ground/edge/backlit/above from the imported occupied bounds (sets `CLOUD_BOX`/`FOCUS_BOX` from `flagship/bookmarks.ts`); harness `report()` carries `import` (info), `pageMs`, `error`, `compare`. An import error is shown on the page and reported with `console.warn`, so captures of failing files still exit 0.
Open issues:
- **`/@fs/` limit.** vite's `fs.allow: ['../..']` resolves to the checkout that runs the server. In this worktree the main checkout's `artifacts/research/...` returns 403 (verified). I copied the six test VDBs (APFS clones, gitignored) to `<worktree>/artifacts/research/{vdbs,disney-cloud,nubis-pack/ParkouringCloud}` and used `/@fs/<worktree>/artifacts/research/...`. Run from the main checkout the URLs in the task work as written (`artifacts/research/nubis-pack/extracted/...` with `%20` for spaces). Not changed: `vite.config.ts`.
- Fog/sdf noise: `smoothNoise` uses mulberry32 + Box-Muller, not numpy PCG64, so a seed gives the same statistics but not the same field as the Python converter (pack mode has no noise, hence exact parity there). Fog/sdf output was not compared to hython output byte for byte.
- sdf mode differs from Python on purpose: depth = deeper of the VDB distance and the mask EDT, because a narrow-band level set is a constant -background below a few voxels (Python would give a thin shell). Not compared against hython.
- Pure-TS inflate is the slow part for ZIP files: bunny_cloud (80 MB) parses in about 2.5-4.3 s. Blosc lz4 and uncompressed files parse in tens of ms. Moving ZIP to `DecompressionStream('deflate')` would need an async path; not done.
- Not supported (clear errors): non-float grids (vec3, int, points), non-5-4-3 trees, rotated/sheared transforms, instanced grids, Blosc codecs other than lz4 (blosclz/snappy/zlib/zstd), active root-level tiles. Anisotropic voxels are resampled per axis. Level sets whose inactive exterior is not `background` are untested.
- Page auto-scale: without `?width`/`?scale`, a cloud under 600 m wide is scaled to 1500 m (artist VDBs are in real-world units). The library itself never auto-scales; it only does what `worldScale`/`targetWidthMeters` say.
- The 6 test VDBs under `<worktree>/artifacts/research` and `cloud.0001-zstd.vdb` are scratch (gitignored), not deliverables.
