# P3-C1 Distant sky layer (Nubis vertical-profile 2.5D)
Status: ready for review (known visual issues below)
Changed: new `packages/runtime/src/{sky-layer.ts,shaders/sky-layer.wgsl.ts}`; `runtime.ts` (sky targets, `runtime.skyLayer`, pass, composite bindings), `shaders/{composite,frame,density}.wgsl.ts`, `index.ts`; small shared edits in `generate/{shaders,weather,volume-generator,index}.ts` (not in my list: `BILLOW_WGSL`/`billowAt` split out, weather `window` option + `border: 0`, exported `NVDF_DEFAULTS`; generator output unchanged); `examples/lab/cloudscape-gen/main.ts` (`?sky=1`, `sky_<setting>=N`, `sky_rim`, `sky_window`, `sky_res`, bookmarks seamEast/seamSouth/seamNorth/seamHigh).
Verified:
- `pnpm check` green. Density parity page `pass: true` (formula max 2.8e-7, e2e 4.3e-3, same as P2-04). `runtime-tests/generate/` exits 0 (512x512x64 still 49.5 ms).
- Flagship ground/edge, layer off, before vs after code, 1920x1080: mean |d| 0.079 / 0.055 (run-to-run noise floor from P2-04: 0.03-0.06). The composite merge is gated by `frame.skyEnabled`; the density refactor (`cloudDensityShaped`) is the same math.
- captures: `work/captures/P3-C1/{ground,horizon,above,seamEast,seamSouth,seamNorth,seamHigh}.jpg` (2560x1440, `preset=cumulus&sky=1`), `off-horizon.jpg`, `off-seamNorth.jpg` (same views, layer off).
Weather map world mapping: the generator samples its weather texture at uv = (voxel + 0.5) / dims over the box footprint, i.e. uv = (xz - boxMin.xz) / boxExtent.xz (map row = world z). The weather fields are procedural in uv (fBm, Worley), so evaluating the same `weatherMain` at uv outside [0,1] continues the same field. The sky layer bakes that function once (`encodeProceduralWeatherMap` with `window` + `border: 0`) into a 2048^2 rgba8 window of 51.2 km centred on the box (25 m texels), using the options you pass to `skyLayer.configure({ weather, shape })` (the same objects given to the generator).
Near/far agreement:
- Same weather function, parameters, seed and uv anchoring; same shaping law (`f = s - h^p`, base lift, coverage threshold, topFraction, domeExponent, scale/detail/profile formulas from the generator, depth proxy = min(f*depthScale, height above base)); the generator's billow code is shared (`BILLOW_WGSL`, same seed and box-relative coordinates, octaves fade out with distance).
- Same up-rez (`cloudDensityShaped`, the body of `cloudDensity`) and same `cloudInScatter`/`cloudEdgeFactor`/`cloudPhase`.
- Hand-off: the generator fades coverage by smoothstep(0, B, e) at the box rim (B = `border` x box size, e = distance inside the edge). The sky layer uses the complement 1 - smoothstep(0, B, e) on the same coverage, so the two add up to the full weather across the rim; far = 1 outside, 0 deeper than B inside. Composite orders the two by mean cloud distance (so sky cloud in front of the box covers it).
- Verified by eye only (box clouds line up with the layer: seamNorth shows the voxel lobes and the sky layer around them). I did not numerically diff the baked window against the generator's map.
Measures (min of 4 runs; the GPU is shared with other agents, single runs vary by +-0.2 ms):
- Sky pass at 2560x1440, 1/4 res (640x360): ground 0.66 ms, seamNorth 1.28 ms, horizon (worst) 1.35 ms. Target 1.5 ms: pass. Composite with the merge: no measurable change (0.71 vs 0.77 ms). Defaults after tuning: maxDistance 30 km, stepMin 16 m + 0.006 d, cutoff 0.1, 384 steps, billow octaves fade 3/2/1 by distance, lighting cached along the ray beyond 3 km.
- One-off: weather window bake on first enabled frame (a single 2048^2 compute) and async pipeline compile (the layer skips frames until it is ready).
- Layer cost is paid only when enabled; memory +1.8 MB colour +1.8 MB depth at 1440p.
Open issues (honest):
1. Image quality of near sky clouds (< ~3 km, e.g. the foreground clouds in `horizon`/`seamEast`): hatch/dither from the static per-pixel jitter at 1/4 res, and some vertical "cliff" edges on cloud sides. The cliffs are real geometry in the layer (a depth debug view shows them as distance steps) and persist with skip, light cache, billow octaves, upsample rejection and window texel size each ruled out; I did not find the exact cause (suspect steep weather-field creases from the Worley cells; the voxel path hides them with the SDF profile). The layer is meant for the distance; P3-C2 (16-frame temporal) should remove the hatch. Cliffs may need a gradient-aware depth proxy.
2. Sky-layer bases/shadowed parts read darker and greyer than the voxel ones (sun in-line + 3 cheap samples vs the light grid; `lightDensityScale` applied to the far samples). Tuning knob: `skyLayer.settings.densityScale`, lighting constants in `sky-layer.wgsl.ts`.
3. The hand-off is cross-faded, not a hard line, but where a voxel lobe ends at the rim the sky cloud next to it differs in lighting and shape detail, so the boundary is faintly readable in `seamNorth` (vertical edge at the right of the centre lobe). No hard box wall is visible.
4. Horizon band (> 20 km) is mosaic/blocky (1/4 res, thin slivers); curvature is implemented but off (`settings.curvature`); the baked window is static (50 km around the box) and the layer fades out toward 30 km.
5. The 'ground' bookmark places the camera inside the box looking at it: the layer adds clouds only past the rim, so it changes little there.
API: `runtime.skyLayer.configure({ weather, shape, window?, rimWidth? }); runtime.skyLayer.settings.enabled = true`. Settings: densityScale, maxDistance, maxSteps, transmittanceCutoff, stepMin, stepRel, depthScale, curvature, resolutionScale. Off by default.
