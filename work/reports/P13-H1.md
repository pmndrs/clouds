Design notes / deviations:
- **No `DensityInputs.fine` field.** The sky layer and the parity page construct DensityInputs positionally, so adding a field would break files H1 does not own. Instead `cloudDensityFine(p, t, inputs)` reads `sampleModelingHero` when `t < hero.fineDistance`. `fineErosion` is folded into `detailBias` inside bricks: `noise * (1 + bias) * fineErosion`. `cloudDensity` and `cloudDensityShaped` are unchanged.
- **Separate march variant.** One shader with a uniform branch gave 40-150 pixels off by 1-2/255 (Metal codegen), so the march is a separate pipeline variant (`marchWgsl(mode, direct, fine)`). The runtime picks it only when the bound volume has `fine` and `fineDistance > 0`. `setVolume` compiles it with `createComputePipelineAsync` before the swap. Volumes without fine data run the exact pre-H1 shader.
- **Bindings 6-8** (indirection r32uint 3D, pool rgba8 3D, 48 B HeroParams) are always in the layout. `createVolumeBindGroup` binds per-device placeholders when `hero` is omitted (fineDistance 0), so the existing callers (light-grid page, parity page, shadow map, sky layer) need no change.
- **New API.** Settings: `fineDistance` (tier preset: 3000/3000/1500/600/0 m) and `fineErosion` (1). `GpuCloudVolume.fine?: GpuFineOverlay`. Core exports `uploadFineBricks`, `heroUniformData` and `HERO_UNIFORM_BYTES`. The CPU packer and the reduction (`hero/bricks.ts`: `packFineBricks`, `reduceFineLattice`) are not exported from core; H3/H4 should re-export them from `import`. A change to fineDistance or fineErosion cuts the temporal history.
- **Brick allocation margin.** `packFineBricks` gives a cell a brick when a set voxel lies within `margin` (default 1 = the apron). Empty cells fall back to the coarse field, whose filtered halo reaches about 1.5 coarse voxels past the fine occupancy, so the page uses margin 3 (= 1.5 x ratio). H3 should use the same rule for heroes, or the coarse halo shows in empty cells next to bricks.
