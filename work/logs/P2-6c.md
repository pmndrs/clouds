# P2.6c: Houdini cumulus, one VDB per stage

**What:** `scripts/houdini/cumulus-stages.py` (hython, Houdini 21.0.792 Indie) builds one cumulus tower with the SOP cloud
tools and writes a density VDB after each of four stages. It also saves the network as `houdini/rigs/cumulus_stages.hip`
(network boxes and a sticky note per stage, one `export_*` ROP per stage).

```bash
HYTHON=/Applications/Houdini/Houdini21.0.792/Frameworks/Houdini.framework/Versions/Current/Resources/bin/hython
$HYTHON scripts/houdini/cumulus-stages.py --render     # about 15 s: 4 VDBs + .hip + previews + sheet
```

- VDBs: `assets/clouds/houdini-stages/cumulus_{1_lobes,2_replicate,3_billowy,4_wispy}.vdb`. Grid `density` (fog, 0..1),
  metres, y up, flat base at y = 0, 12 m voxels, 1.5 / 2.2 / 3.8 / 4.4 MB (committed; deterministic, the rerun gives the same bytes).
- Size: 3.0 km wide (x -1458..1530), 2.0 km tall (6..2010), 1.7 km deep at stage 4.
- Sheet: `work/captures/P2-6c/sheet.jpg` (2 x 2, same side-on camera, sun from the upper left). `report.json` has the params and
  per-stage stats (active voxels, mean density, bbox, cook time).

## Which stage stops it looking like balls

**Stage 3, billowy noise.** Stage 1 is plainly a pile of spheres. Stage 2 (replicated smaller lobes) is still spheres, just
smaller ones: a cauliflower or bubble foam with sphere edges everywhere along the silhouette. Billowy noise is the stage where
the lobes merge into billows with varied size and the round outlines go away. Wispy noise (stage 4) is the finish: it tears
and streaks the rims (fibrous, sheared edges) and makes the edge crisper and less uniform, but on its own it would not fix a
sphere cloud. The owner's warning holds: shapes alone (stages 1 and 2) read as balls; the noise passes are what make a cloud.

## Recipe (what our generator should copy)

Built at the tools' native scale (1 Houdini unit = 750 m, scaled to metres on export). Every length below is given in metres.
The tools' scatter counts are not scale-invariant (see the note in `scripts/vdb/authoring/frog.py`), so author at their
native scale and scale the result.

1. **Lobes** = 3 x Cloud Shape Generate on one point each: congestus core (length 2, width 0.25) at x = 0, two mediocris flanks
   (length 1) at x = +-710 m, z offsets +-100 m; flatten bottom on, secondary scatter on (3 iterations). That gives 686 spheres,
   radius 75-170 m (p5-p95). Then VDB from Particles (fog only, band 3 voxels) and Cloud Clip (plane y = 0, the flat base).
2. **Replicate** = Cloud Shape Replicate, surface scatter, point separation 68 m, scale by noise 0.8-1.6 (element size 300 m),
   up-vector falloff (bias 0.35) and a directional size boost (1-1.6x on up-facing lobes): about 110 k children, radius 55-125 m.
   Then a second rung: seeds = a random 3 % of the first-rung lobes whose normal has N.y > -0.2 (about 3 k), Replicate with
   point separation 26 m, scale 0.8-1.5 (element size 110 m), up-vector falloff (bias 0.5): about 1.85 M lobes, radius 20-40 m.
   Spheres whose centre is below the base are dropped, then the same fog + flat base as stage 1. Replicating all first-rung
   lobes (no thinning) gives tens of millions of spheres and never finished, so the second rung must be seeded sparsely.
3. **Billowy noise** = Cloud Billowy Noise on the fog. How it works: it turns the fog into an SDF at iso 0.5, **displaces the
   surface along its normal** by a noise and turns it back into fog, so it moves the surface outward and inward (it is
   displacement, not erosion of density). Settings: simplex fBm, 5 octaves, roughness 0.5, element size 340 m, amplitude 75 m;
   3 iterations, each with amplitude x0.45 and element size x0.38 (340 -> 130 -> 50 m features, 75 -> 34 -> 15 m
   displacement); Worley details on (blend 0.8, erosion 0.6, element size x2): the cellular term carves the cauliflower valleys;
   noise advection on (amplitude x0.5, element size x0.6): a domain warp so the billows look rolled rather than uniform;
   up-vector falloff on (bias 0.6), so the displacement is strongest on up-facing surfaces and weaker on flanks and undersides.
   Clipped flat at y = 0 again.
4. **Wispy noise** = Cloud Wispy Noise on the result. How it works: it **advects the density** through a velocity field built
   from a flow noise (`aaflow`, curl-like), so it smears and tears material sideways instead of displacing a surface. Settings:
   amplitude 190 m (0.25 units), element size 90 m, 6 octaves, roughness 0.55, 2 iterations, 2 substeps. Height mask: the
   node's "scale by bounding box" along y (bound min 0, max 1). As set here the mask's effect is not clearly visible on the
   sheet: the tearing looks about the same at the top and the base. A first try with amplitude 45 m changed almost nothing (mean
   density 0.7854 -> 0.7851), so wispy noise needs a large amplitude compared with the voxel size before it does anything.

Total cook time is about 5 s at 12 m (each node 0.2-2 s).

## The check: render route

- **Karma (husk) failed twice**, so the sheet does not use it. The volume rendered as 128 m blocks (the VDB leaf size at 16 m)
  and everything above the camera height came out black. It looked the same with the `kma_pyropreview` shader and with the
  MaterialX recipe from `scripts/vdb/reference/build_rig.py`. I stopped after two tries as the brief said. The Karma code is
  still in the script behind `--karma` (4 s per frame) for whoever wants to debug it. Guesses, not checked: the volume LOP
  field binding, or the x750 VDB transform.
- **The sheet uses a numpy preview inside hython** (`preview_render`, 0.6 s per frame): an orthographic side view, single
  scattering, sun direction (+0.8, -0.6, 0), shadow found by marching the grid toward the sun, an ambient sky term reduced by
  the optical depth above each voxel, extinction 0.04 /m at density 1. It has **no multiple scattering**, so the shadowed core
  is too black. That is the preview's fault, not the cloud's. It shows the surface, and the surface is what this check is for.
  Do not judge the lighting from it.

## Proposed next

- Our generator: copy the order (big lobes -> sparse rungs of smaller lobes on up-facing surfaces -> SDF-displacement billows
  with Worley valleys and a domain warp, strongest facing up -> advection-style wisps). Note that the billows are applied to an
  SDF of the lobe union (displacement), not as density erosion.
- If we want a proper Houdini reference image, fix the Karma route (separate small task) or render a VDB in Blender Cycles with
  `scripts/render-cloud-reference.py`.
- The wispy height mask needs a check with the node's control ramp (not used here), so it acts on the base and the undersides only.
