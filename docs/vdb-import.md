# Offline OpenVDB fog import

The VDB path is an offline conversion bridge into the existing CLDA dense
asset contract. It does not add a browser VDB parser or sparse runtime. The
source grid must be a scalar OpenVDB **fog volume**; level sets and signed
distance grids are rejected because their values do not have cloud-density
semantics.

## Converter

Run the standalone converter with an OpenVDB Python binding available in the
same Python environment (the `openvdb` or `pyopenvdb` module is accepted):

```sh
python3 scripts/convert-vdb.py cloud.vdb build/cloud.clda \
  --grid density --resolution 128 --value-range 0 1
```

`--resolution N` creates an `N×N×N` destination. Use `--resolution X Y Z` for
an anisotropic destination. `r8unorm` is the default and maps the declared
value range to 0–255. Use `--encoding r32float` to retain float values. The
converter rejects out-of-range r8 values unless `--clamp` is supplied.

Every run checks destination dimensions, voxel count and payload bytes before
allocating the dense destination. The defaults are 4096 per axis, 256³ voxels
and 256 MiB; lower them for CI or constrained machines with
`--max-dimension`, `--max-voxels` and `--max-payload-bytes`.

The output is a normal CLDA v1 asset. A sidecar named
`OUTPUT.clda.json` is written beside it and records the source grid name and
class, active index bounds, source dimensions, world bounds, voxel spacing,
background, encoding, value range and whether clipping was used. The world
bounds are computed by transforming the active voxel box expanded by half a
voxel on each side. This preserves the source world scale and spacing in the
dense field's bounds and sidecar even though CLDA itself has no arbitrary
matrix metadata field.

The TypeScript adapter in `packages/tools/src/vdb.ts` accepts the same
normalized information when another native bridge already has the grid in
memory. It validates finite values, affine transforms, positive spacing and
fog semantics, then performs bounded nearest-size or trilinear resampling.
The dense descriptor stores an axis-aligned world box, so rotated, sheared or
negative-axis transforms are rejected before sampling instead of being silently
flattened into a misleading AABB.
Use `convertVdbFogGridToDensity` for that adapter path. Its `values` array is
already expanded to include the OpenVDB background and uses x-fastest order.

## Local capability check

The regular PATH probe found no `openvdb` or `pyopenvdb` module. Explicit
inspection found Houdini 21.0.671 and 19.5.303 under `/Applications/Houdini`.
Houdini 21.0.671 works headlessly after sourcing its `houdini_setup`; the
Houdini 19.5.303 installation is retained only as an older fallback. No
license prompt was bypassed.

The native bridge is [`scripts/convert-vdb-houdini.py`](../scripts/convert-vdb-houdini.py).
Run it in the initialized Houdini environment:

```sh
cd /Applications/Houdini/Houdini21.0.671/Frameworks/Houdini.framework/Versions/Current/Resources
source ./houdini_setup
hython /path/to/WebGPUClouds/scripts/convert-vdb-houdini.py \
  /path/to/input.vdb /path/to/output.clda --grid density
```

It reopens the source VDB, checks fog semantics, records active/positive voxel
counts, mass and peak density, checks representative nonzero/peak readback
parity, verifies the declared r8 quantization budget, then writes CLDA and a
metadata sidecar. The script bounds bridge payloads at 16 MiB. Its HOM calls
follow SideFX's [`hou.Geometry`](https://www.sidefx.com/docs/houdini/hom/hou/Geometry)
and [`hou.VDB`](https://www.sidefx.com/docs/houdini/hom/hou/VDB) APIs, including
`loadFromFile`, `saveToFile`, `activeVoxelBoundingBox`, `voxelRangeAsFloat`,
and `isSDF`.

## Validation and limitations

The converter reads the selected grid's class, active bounding box, transform,
spacing, background and scalar values. Missing class, transform, bounds or
background metadata fails closed. Unknown grid classes are not guessed as fog;
level sets explicitly fail. Animated sequences, multi-channel grids, sparse
GPU storage and VDB writing are outside this bridge. Quantization error for
r8 output is controlled by `--value-range` and should be measured against the
original scalar values before publishing an asset.

The Python adapter follows the official OpenVDB Python access pattern of
`readAll()` returning grids plus metadata and
`getConstAccessor().getValue()` for coordinate reads; see the [OpenVDB Python
documentation](https://www.openvdb.org/documentation/doxygen/python.html).

The VDB converter is intentionally not wired into the package root export in
this change. After review, expose the API from `packages/tools/src/index.ts`
with the explicit export block for `./vdb`; package manifests do not need a
new runtime dependency because the native reader is an offline Python tool.
