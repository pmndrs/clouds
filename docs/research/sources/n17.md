## In one paragraph
A conceptual talk, not a recipe. Its unique content is (1) the **height-gradient construction**, `remap * remap`, with cloud type shifting the in/out points (p.28-32), (2) coverage as an erosion remap, and the one exact **anvil formula** (p.40, p.46-50), (3) the **cloud map**: RGB, built from one low-frequency gate noise times Perlin (R) and Perlin-Worley (G) footprints, with type from another low-frequency noise (B) (p.53-58), (4) the **authoring pipeline**: Decima-editor controls -> weather-simulation shader -> RGB texture -> optional image-editor paint-over -> cloud map; weather states, cycles, a scheduler and zones (p.67-72), (5) lighting changes: two-lobe HG, two-Beer multiple-scatter, in-scatter probability (p.76-93), (6) ray-march numbers (54-96 steps, 10 zero samples, 5 cone taps) and the alpha = 0.5 haze depth (p.95-101). **The code slides (density sampler, lighting, ray march) are not in this PDF**: the text only says "[code implementation example in the slides]" on p.36, 89-92, 95-96. Nothing here prints numeric gradient constants for the three types, and nothing prints the weather simulation's noise frequencies or the map's world size unambiguously.

## Key ideas (shape, layering, authoring; story not repeated)
- **Two inputs drive most of the density model: coverage and type** [p.27]. Everything else is a per-weather-state constant (skew, anvil, speed, direction, density), "treated the same at every sample" so not stored in the map [p.59-60].
- **Height gradient = two remaps multiplied** [p.28]; moving the four points gives every cloud stage in the "minus" (low) layer. Type orders the set stratus -> stratocumulus -> cumulus and "serves as the value which modifies the in and out points" [p.29]. The in-game gradient strips are on p.30-32 (settled below).
- **Noise composite is remapped, not multiplied**: `base = remap(low_freq, high_freq, 1, 0, 1)`, because remapping "prevents a loss of too much density at the core" [p.36]. Detail is "carving a block of clay" where the detail is already in the clay [p.39]. Renders without noise / low / low+high are p.37-39.
- **Coverage is an erosion remap and inflates clouds as it rises** [p.40-44] (literal sign caveat in Formulas).
- **Animation is detail-only**: wind offset plus a height skew of 500 on the sample position; "the general shapes do not change, but the details do" because the coverage signal is not animated [p.45]. A deliberate departure from the 2015 prototype, where the simulated sky evolved.
- **Anvils are a coverage inflation near the top of a cumulus** [p.46-49], and the wind vector gets an extra variation to skew anvils "in a direction that is not natural but looks cool" [p.49-50].
- **Shipped game models only the low layers; cirrus is a 2D texture lookup**; alto/cirro volumetrics are "experiments" [p.50, p.105-106].
- **Cloud map = gate x footprint x type** (below). R footprint is Perlin (connected formations, p.56); G footprint is Perlin-Worley (isolated islands with "connective tissue", p.57). The artist picks which one the density sampler uses [p.56].
- **Painted override**: any texture can replace the simulated cloud map; Schneider edited the simulation's RGB output in an image editor (add/remove coverage and type regionally), blended several maps into a "Frankencloudscape", and fulfilled "I want a hole right here" by painting black [p.67-68].
- **Weather states are presets; a scheduler blends them** (below).
- **Layering as composition** (art references): Constable's cloud "curtains" for depth layers [p.60], Bierstadt's cumulus pillars that extend the mountains vertically [p.61], Ansel Adams' tonal contrast for desert cumulus [p.62, p.65]. Goals list [p.63]: set mood for encounters/exploration/cutscenes, extend the landscape, realistic art-directable structures, evolve details not formations, behaviour changes with weather.

## Formulas and constants (exact; PDF page)

**Height gradient, the settled answer** [p.28-32]
- Printed: `stratus = remap(h, 0.0, 0.1, 0.0, 1.0) * remap(h, 0.2, 0.3, 1.0, 0.0)` [p.28], same expression drawn for the type axis [p.29]. `remap` is the **unclamped** `new_min + ((v - old_min)/(old_max - old_min)) * (new_max - new_min)` [p.28]; any clamp is not shown.
- **The type-blend formula is not printed.** The text only says type "modifies the in and out points" [p.29]. So **GPU Pro 7's omission is not settled by N17 either**; the constants below are measured, not sourced.
- Measured from the in-game gradient insets (p.30-32, 110 dpi render; box 104 px tall; heights as fraction of the layer, +-0.02; "rise" = density 0 -> 1 going up, "fall" = 1 -> 0):

| Type (inset) | rise (bottom ramp) | plateau | fall (top ramp) | Printed-form guess `(a,b,c,d)` |
| --- | --- | --- | --- | --- |
| Stratus [p.32] | about 0.01 -> 0.07 | to about 0.10 | about 0.10 -> 0.18 | (0.01, 0.07, 0.10, 0.18) |
| Stratocumulus [p.31] | about 0.03 -> 0.16 | to about 0.32 | about 0.32 -> 0.47 | (0.03, 0.16, 0.32, 0.47) |
| Cumulus [p.30] | 0 -> about 0.09 | to about 0.65 | about 0.65 -> 0.79 | (0.00, 0.09, 0.65, 0.79) |

  The cumulus rise matches the printed `remap(h, 0, 0.1, ...)`, but the printed **stratus fall 0.2-0.3 does not match** the stratus inset (0.10-0.18): the printed formula is an example, the shipped curves are different. All three are drawn in the same box, so the cumulus top at ~0.8 of the layer means the cumulus gradient **leaves the top fifth empty** (room for the anvil band, p.46: starts at h = 0.7).
- **A blend by type that reproduces the three insets** (our inference, not printed): `a(t) = piecewise-linear(0.01, 0.03, 0.00)`, `c(t)`: 0.10 / 0.32 / 0.65 at t = 0 / 0.5 / 1, `d(t)`: 0.18 / 0.47 / 0.79, `b(t)`: 0.07 / 0.16 / 0.09; then `grad = remap(h,a,b,0,1) * remap(h,c,d,1,0)`. Compare GP7 Fig 4.10 measured values in `gp7.md` (stratus peak 0.08, "cumulus" plateau 0.20-0.42, cumulonimbus to 0.75): GP7's middle panel (0.20 -> 0.42 -> 0.60) sits between this table's stratocumulus and cumulus rows, so GP7's three are **not the same curves** as N17's.

**Perlin-Worley** [p.34]: `pw = remap(perlin, 1.0 - worley, 1.0, 0.0, 1.0)`. Intent: subtract the web-like Worley from low-density Perlin so round shapes appear there. Hillaire's generator (github.com/sebh/TileableVolumeNoise) and Guerrilla's Houdini COP asset (`bit.ly/nubisnoisegen`, outputs a tiling 2D texture array to convert to 3D) are the two offered tools [p.34-35]. Local dump of that asset: source id `noise`.

**Base noise** [p.36]: `base_cloud = remap(low_freq_noise, high_freq_noise, 1.0, 0.0, 1.0)`. The old minimum is the high-frequency noise. The preview strip on the slide shows 4 low-frequency channels (smooth Perlin-Worley then 3 finer Worley) and one small high-frequency strip.

**Coverage** [p.40]: `cloud_with_coverage = remap(noise, cloud_coverage, 1.0, 0.0, 1.0)`. **Sign caveat (our reading)**: read literally, a larger `cloud_coverage` is a *higher* threshold and gives *fewer* clouds, yet the slides say raising coverage inflates [p.41-44]. It is consistent only if the threshold is `1 - coverage` (Takram's `factor = 1 - cov * grad`, `density.wgsl.ts:195`) or "coverage" means "erosion amount". Treat the printed form as a sign shorthand.

**Anvil** [p.46-50]: `coverage = pow(coverage, remap(height, 0.7, 0.8, 1.0, lerp(1.0, 0.5, anvil_bias)))`. With cloud amount `cov` in 0..1 (the consistent reading), a smaller exponent raises it, so the top inflates. Exponent table for `bias = 1` (X = 0.5) with the unclamped `remap` from p.28: h = 0 -> 4.5, 0.5 -> 2.0, 0.7 -> 1.0, 0.8 -> 0.5, 0.9 -> 0.0, 1.0 -> -0.5. **Open**: if `remap` is unclamped the bias also thins the lower body (exponent > 1 below 0.7, coverage^4.5 at the base) and exponent < 0 over-fills above 0.9; the slide does not say. A clamped remap (exponent in [X, 1]) would only inflate the top. Test both. At `bias = 0` the exponent is 1 everywhere. The bias is a weather-state scalar [p.59].

**Wind/skew** [p.45]: `p += wind_direction * time_offset; p += height_fraction * wind_direction * 500.0;` (500 is the same constant as GP7's `cloud_top_offset`). The cloud map is **not** advected, only the sample-space noise.

**Cloud map channels** [p.53-58] (the exact answer to "what are the channels"):
| Ch | Content | How built |
| --- | --- | --- |
| R | cloud coverage, Perlin footprint | low-frequency gate noise x several higher-frequency **Perlin** noises: connected formations |
| G | cloud coverage, Perlin-Worley footprint | same gate x higher-frequency **Perlin-Worley**: isolated islands with connective tissue |
| B | cloud type | another low-frequency noise: 0 stratus, 0.5 stratocumulus, 1 cumulus |
Both R and G are coverage; the density sampler uses one of them by artist choice [p.54, p.56]. **Contradicts GP7** (G = precipitation) and `gp7.md`/`hzd15` "R coverage, G precipitation, B type": in 2017 there is no rain channel in the map. The gate noise is "large regions where air masses overlap" [p.55]; with all-100% coverage the map is a flat yellow square (R = G = 1) [p.54]. Number of octaves and frequencies are not stated ("several"); the p.55 gate has about 3-4 large blobs per map side. Coverage area "about 100 square kilometers" [p.54]: ambiguous (10 x 10 km or 100 x 100 km?); GP7 says 60,000 x 60,000 m, NE22 16 x 16 km, so do not trust the number.

**Weather state** [p.59-60]: map plus constants {skew, anvil bias, movement speed, movement direction, cloud density}. Counts [p.72]: **10 regional zones, 70 small zones** (e.g. bandit camps where the art director "always wanted foreboding dark clouds").

**Weather scheduling** [p.70-72]: states ("Cloudy", "Clear", "Storm") are grouped into a **Weather Cycle** per zone; the **Weather Scheduler** chooses the next state at random, with the allowed states gated by time of day (no cumulus in the morning) [p.70]. Special cycles (e.g. "Big Boss Fight") override regional ones. Transition = a **simple lerp of the whole state over 10-30 s** [p.71]. On entering a zone the scheduler replaces the next scheduled state with a random state of the new zone and starts blending at once [p.72]. "Weather simulation" is a **shader** driven by controls in the Decima editor [p.67-68]; its frequencies and time behaviour are not given.

**Lighting changes** (parked, but exact) [p.75-93]
- Model is an **attenuation model**: only subtract from full light; three probabilities: directional scattering, absorption/out-scatter (with in-scatter), in-scatter [p.76].
- HG as printed [p.77] ends `/ 4.0 * PI` (same bug as GP7). Two-lobe: `E = max(HG(cos, ecc), silver_intensity * HG(cos, 0.99 - silver_spread))`, `ecc = 0.6` [p.78-82]. Reason: ecc fit for midday gave no sun glow at sunset; ecc = 1 gave highlights but made clouds 90 degrees from the sun too dark.
- Multiple-scatter approximation after Wrenninge [p.84-85]: `E = max(exp(-d), exp(-d*0.25) * 0.7)`, with the second term **ramped down as the view-light angle decreases** (ramp not printed; code in the hidden slide).
- In-scatter probability [p.89-92]: `depth_probability = 0.05 + pow(lodded_density, remap(h, 0.3, 0.85, 0.5, 2.0))`, `vertical_probability = pow(remap(h, 0.07, 0.14, 0.1, 1.0), 0.8)`, product. First form used exponent 2.0 and was "too dark" at the edges; the height-varying exponent (0.5 low, 2.0 high) relaxes that. Density is sampled at a **low LOD**. The note says a direction term keeps it from being purely directional (code hidden). Replaces the 2015 powder sugar. No clamp anywhere, for HDR [p.93].
- Here `h` is the **height fraction in the same gradient space** as the density model; the vertical gradient 0.07 -> 0.14 matches the stratus rise, "depends on how you define your height gradients" [p.92].

**Ray march and cost** [p.95-98]: spherical shell; **54 to 96 steps** (up to horizon); large cheap steps with low-LOD low-frequency noise only (high-frequency noise only subtracts from the edges), then short full steps; **10 consecutive zero-density full samples** return to large steps; stop at alpha 1 or shell end; **5 light taps** in a light-aligned cone with falling LOD at each non-zero full sample (GP7: 64-128 steps, 6 zeros, 6 taps). PS4 timings: reprojection only 22 ms; + LOD/adaptive step 8.1; + light only when density non-zero 3.34; + cull below the horizon 1.81; + depth culling 1.2 [p.97-98]. Depth culling uses `max()` of a low-LOD depth so thin occluders (trees) do not cause reprojection artifacts [p.98]. Below the horizon the sphere "begins to tile noticeably", so those pixels are skipped [p.98].

**Horizon/haze rule** [p.99-101]: the ray march outputs RGBA = (direct light, **atmospheric blend factor**, ambient, alpha). During the march record a depth when **alpha first reaches 0.5**; after the march sample the accumulated atmospheric scattering at that depth; store in G; the post pass uses it as the lerp factor between cloud colour and sky colour. `atmospheric_blend_factor = GetAtmosphere(depth, angle)` [p.101]. (Our runtime uses the opacity-weighted mean distance from NE22 p.187, a later method.) **Light shafts** (Mitchell GPU Gems 3 ch.13): bright sun highlight where not occluded -> offset radially away from the sun -> radial blur -> use as a **mask on the Mie term** of the atmosphere shader, not added to the scene, so shafts follow Mie colour and are not drawn on near scenery [p.102-104].

## What we already do / don't / what to try
Runtime: `packages/runtime/src/procedural/density.wgsl.ts` (Sky Pro and Takram shapers), `textures.ts`, `settings.ts`, `trace.wgsl.ts`.
- **Type-based height gradient**: we have neither. Takram uses a semicircle on `pow(h, bias)` per layer (`density.wgsl.ts:177-181`, `shapeAlteringBias 0.35` `settings.ts:144`), one fixed curve per channel, no continuous type axis. Sky Pro has a flat-base mask and a rising top (`:104-110`). **Try**: the three trapezoids above plus a type blend (`a(t)..d(t)`); better, the NE22 table form, `ne22.md`.
- **Anvil bias**: still missing. The existing suggestion in `procedural-shape.md` M7 is right except it should expose a clamp choice (see exponent table). For Takram insert before `density.wgsl.ts:195`; for Sky Pro apply to `coverage` before `:109`.
- **Wind skew**: Sky Pro has it (`windSkew`, `:98`), Takram none; N17 constant is 500 per layer height.
- **Cloud map**: Sky Pro bakes one Perlin fbm channel (`textures.ts:97-103`: R only, "mass + detail + weatherCoverage"). N17 wants three channels: gate, footprint A (Perlin), footprint B (Perlin-Worley), and a separate type noise. Our Takram path reads a loaded `local_weather.png`. **Try**: bake a 3-channel map where R = gate x Perlin, G = gate x Perlin-Worley, B = type, selectable footprint; this is the cheapest way to get isolated islands vs connected sheets (layering and shape).
- **Coverage**: Takram `factor = 1 - cov*grad` (`:195-196`) is the consistent-sign version of N17 p.40; the `* cov` multiply from GP7 is absent.
- **Noise remap, not multiply** [p.36]: Takram does `procRemap4(density, (1 - shape)*amount, 1)` (`:215`), the same idea; detail is `modifier*0.5` (`:223`). Fine.
- **Weather scheduler**: nothing in the runtime. A lerp between two full parameter sets over 10-30 s with time-of-day-gated random choice is trivial and gives the "clouds change with weather" behaviour [p.70-72].
- **Painted override**: our weather texture path already accepts any PNG (Takram); a viewer-side paint tool for R/G/B would match the p.67-68 workflow.
- **Haze**: `trace.wgsl.ts:312-314` uses mean distance; N17 uses the alpha = 0.5 depth. Not a contradiction (NE22 supersedes). Our step counts (`trace.wgsl.ts:24-27`: coarse 4x until hit, back to coarse after four empty steps, six cone taps) differ from N17 (10 empties, 5 taps).
- **Sun-glow two-lobe HG** and the in-scatter probability are lighting; keep as the P2 reference.
