## In one paragraph
The talk splits the world into three solvers that all share one idea: a 2D "Nubis Data Field" (NDF) supplies a few per-column scalars and a procedural/analytic profile turns them into a "dimensional profile" (0..1 base density envelope) that a tiled noise composite is subtracted from. **Skies** = vertical-profile model (5 channels) + 2.5D thin-cloud model (2 channels), with NDFs generated procedurally then overridden by hand-painted and regional "Influence NDFs". **Environments** = an "envelope model" (min/max height, type, density, distance) for orographic cloud hugging terrain, ray-marched with cone steps. **VFX** = a superstorm (mesocyclone, anvil, rotation, lightning) built from Influence NDFs plus a rotated noise lookup. Everything is a density function of position, so no volume authoring is needed except at the end (NVDF, p.192+).

## Key ideas (shape, layering, detail)
- **Vertical-profile NDF channels, five**: min height, max height, coverage, bottom type, top type; layer 256 m..2048 m [p.20]. 2.5D NDF has two: coverage, type [p.64]. Envelope NDF has min height, max height, type, density, distance (+ upper/lower angle at locations) [p.106, 129]. Superstorm influence NDF has min/max height, coverage, bottom type, top type plus a Superstorm Mask [p.139].
- **Top type is a 1D axis of profiles, 0 -> 1: stratus (thin band at the bottom), stratocumulus (taller band with a stepped upper edge), cumulus (tall column, soft top)** [p.21]. The p.22 render shows the full table: height up, top type right; a white filled floor (the first ~25% of height is solid for every type), then the top edge climbs in two soft steps (stratus -> stratocumulus -> cumulus) with blurred, not hard, steps. So types are authored as a 2D lookup image (not a formula) and interpolated by `top_type`.
- **Bottom type** is a second 2D table: height up, bottom type right [p.26]. Visually a vertical gradient (bright top, fading to black at the base) whose lower cutoff is sharper than the upper fade; bottom type moves that cutoff/softness. Render at p.27 (bottom type 0). Corrected 2026-10-10: the N3 s18 table data show type 0 is the sharp-onset, flat/crisp base and type 1 the slow ragged ramp; the p.27 render alone is ambiguous (see `n3.md` §7).
- **`vertical_profile = top_table(top_type, h) * bottom_table(bottom_type, h)`** [p.28 shows the two images multiplied], then `dimensional_profile = vertical_profile * cloud_coverage` [p.29]. Min/max height set per cloud where the table is stretched [p.20].
- **Density = noise composite minus the inverted profile**: `saturate(noise_composite - (1 - dimensional_profile))` [p.34]. Coverage therefore lowers the threshold and also fattens the cloud; no separate coverage remap.
- **Noise composite**: 4-channel 128^3; channel R = "Perlin 1-Worley" (Perlin-Worley), others Worley of increasing frequency [p.32-33; thumbnails: channel 1 is smooth cloudy Perlin-Worley, channels 2-4 are progressively finer packed billows]. Frequencies not stated.
- **Wind animation** is only a scroll: `noise_sample_position = sample_position - wind_direction * scroll_offset` [p.37]; the NDF is not advected.
- **Step size** grows with distance: `3 + 60*dist/16384` [p.39].
- **2.5D thin-cloud model**: one `cloud_type` blends three 2D noises, streaky -> wispy -> round [p.65]; coverage is an exponent plus a cubic fade [p.65]. Light uses a cirrus sub-layer with few samples to the sun [p.67].
- **Authoring graph** [p.69]: NDF Generator and NDF Editor both feed Influence NDFs which write the final "Authored NDFs". Influence NDF = the same layers as the profile/2.5D NDF plus a red **Influence Mask** layer [p.75]. Regional sets of procedural NDFs (cumulus in one region, stratocumulus in another, San Francisco example) are layered with regional influence NDFs [p.77]; weather states (calm-cloudy, stormy, ...) are cloudscapes of NDFs [p.78].
- **Why the envelope model exists** [p.91-93]: per sample the profile model costs 3 texture reads (1 coverage + 2 for the profile tables) and a multiply, and it assumes cloud sits in a flat 256-2048 m slab above the player; orographic cloud (photo of valley fog on peaks, p.93) lives at arbitrary heights relative to terrain.
- **Envelope profile = bottom^2 * top^1.5 * edge** [p.97], with edge gradient from the *sample height above terrain* (0..35 m) so clouds fade out on contact with the ground.
- **Billowy/wispy switch height is the cloud type** [p.99]: type 0.25 flips low, 0.5 mid, 0.75 high (billowy above, wispy below, diagram p.99-101).
- **Thin clouds sample a different noise slice** [p.102]: offset in z by up to 40 m for thin clouds.
- **Sharpening exponent 0.27 and height multiplier** on envelope density [p.105]; separate **coarse density** (the profile after ValueErosion) used for ambient and shadow [p.105, 113].
- **Superstorm**: NDF channels as above with a Superstorm Mask [p.139-140; the map p.140 is a tiled noisy texture with a circle for the storm radius]. Anvil = a vertical gradient at the top [p.160] plus a cirrus NDF centred on the storm centre [p.161].
- **Rotation**: noise lookup rotated about the storm centre, speed varying per ring (6 rings, indices 0..5, p.149), plus per-ring skew [p.150]. Reprojection is rotated by the same transform so history stays valid [p.155]. Sky clouds get the same machinery plus a 2D scroll [p.157].
- **Integration** [p.187]: each solver records per-sample distance; atmospheric blend uses the opacity-weighted mean distance, not the first hit.

## Formulas and constants (all re-checked against page text)
- `dimensional_profile = vertical_profile * cloud_coverage` [p.29]
- `cloud_density = saturate(cloud_noise_composite - (1.0 - dimensional_profile))` [p.34]
- `step_size = 3.0 + 60.0 * distance_from_camera / 16384.0` [p.39] (near 3, offset 60, adjustment distance 16384)
- HG normalised, rsqrt form, `num*rsqrt^3/(4 pi)` [p.48]
- `ms_volume = Remap(dimensional_profile*step_size, 0.1, 1, 0, 1) * pow(cloud_coverage*cloud_type, 0.25)`; `*= pow(attenuated_light, cMultipleScatteringDepthPower)`; `*= pow(height_fraction, cMultipleScatteringHeightPower)` [p.54]. The two cMS powers are not given anywhere in the deck.
- `ambient = pow(1 - dimensional_profile, 0.5)` [p.59]
- Accumulation [p.61]: `absorption += d*(1-absorption); intensity += energy*d*(1-absorption)` (note: uses the updated absorption).
- 2.5D [p.65]: `d = ValueRemap(type, 0.5, 1, ValueRemap(type, 0, 0.5, cr_streaky, cr_wispy), cr_round); d = pow(d, 1 - ValueRemap(cov, 0, 1, -0.9, 0.9)); d *= ValueRemap(pow(cov, 3), 0, 0.5, 0, 1)`. Exponent runs 1.9 (cov 0) to 0.1 (cov 1); the cubic fade reaches full at cov = 0.79 (cov^3 = 0.5).
- Envelope [p.97]: `h = Remap(height, min, max, 0, 1); top = (1-h)^1.5; bottom = h^2; edge = Remap(sample_height, 0, 35, 1, 0); profile = bottom*top*edge`. Peak of `h^2 (1-h)^1.5` is at h = 0.571.
- Type switch [p.99]: `blend = Remap(h, type+0.1, type-0.1)`; `composite = lerp(wispy, billowy, blend)`. **The slide prints Remap with only three arguments** (no out-min/out-max), so the output range 0..1 is implied; band is +-0.1 around `type`. Caution: read with the usual `(v - a)/(b - a)` this gives blend 1 (billowy) **below** `type - 0.1` and 0 (wispy) above `type + 0.1`, the opposite of the slide's own diagram (billowy above, wispy below). To match the diagram use `Remap(h, type - 0.1, type + 0.1)` (or swap the lerp ends).
- Noise slice [p.102]: `pos.z += (1 - saturate((max-min)*0.0125)) * 40`. Thickness >= 80 m gives zero offset; 0 m thick gives 40 m. (The slide adds to `.z`, the up axis in their engine.)
- Envelope density [p.105]: `height_fraction * pow(saturate(noise - (1 - profile)), 0.27)`; `inv_edge_signal^3`; `coarse = pow(ValueErosion(profile, 0.04), 0.5) * inv_edge^3 * 5.0`.
- Envelope light [p.112-113]: `direct = exp(-summed) * SampleLongDistanceShadowMap(pos)`; `ambient = pow(1 - saturate(coarse), 0.25) * height_fraction`. Two marched sun samples at 128 m / 256 m (diagram p.110) then the map.
- Superstorm rotation mask [p.155]: `pow(saturate(1 - |xy - centre|/radius), 0.1)` (near flat over most of the disc, then falling sharply at the rim).
- Superstorm attenuation [p.165]: `density_scale = pow(min(1 - dist/radius, 0) + 1, 0.5)`. Note `min(x,0)+1`: as printed this is 1 minus a penalty only outside the radius (dist > radius makes x negative); inside the radius it is exactly 1. The printed form contradicts its own talk: the HFW speaker notes for the same slide (hfw p.78) say density is **increased** for light samples inside the radius. Read `max`: `sqrt(1 + max(1 - dist/radius, 0))` = 1.41 at the centre to 1 at the radius, up to about 1.4x optical depth (see `hfw.md`).
- Ambient blend [p.167]: `blend = min(1 - dist1/radius, 0) * (dist2/height)`. Same `min(...,0)` typo (0 inside the radius, negative outside as printed); with `max` it is `(1 - dist1/radius) * (dist2/height)` in 0..1. The height term's direction is not settled by the slide (hfw p.80 notes say probability decreases with height).
- Glow [p.172]: `pow(1 - d1/radius, 12) * (d2/height) * (1 - saturate(fine_density*5))`.
- Absorption curves shown at p.164: `T = e^-5d, e^-10d, e^-20d` (rain-cloud darkening).
- PS4/PS5 budget [p.183]: 960x540 / 1920x1080; 6 / 10 light samples; 60-90 / 96-180 view samples; blur 2x / 1x; noise MIP 1 / 0; <= 4 ms / 2-3 ms [p.184].

## What we already do / don't / try
Runtime facts (our procedural path is a **Takram/Sky Pro-style analytic model, not Nubis**):
- `packages/runtime/src/procedural/density.wgsl.ts:20-25` documents the HZD-based recipe: height gradient (semicircle on `pow(h, bias)`, `procShapeAltering` :177-179), coverage as inflation `factor = 1 - coverage*heightScale` (:195), 32^3 detail inverted toward the base (:221, HZD s37), linear per-layer density profile (:225-226). It is a four-layer vec4 model with one weather channel set; there is **no top/bottom type table, no per-column min/max height, no dimensional-profile subtraction**.
- `procedural/density.wgsl.ts:5-6` already calls `coarse` the NE "dimensional profile" for ms and ambient. Good.
- Cirrus: `cirrus/bake.wgsl.ts:5-10` bakes the three NE p.65 textures (streaky, wispy, round) as r, g, b plus a fine channel (`:221`); verify `cirrus/render.wgsl.ts` blends them with the p.65 type remap and applies `pow(d, 1 - remap(cov, ..., -0.9, 0.9))` and the `cov^3` fade.
- `generate/weather.ts:52-55,153-154` has the HZD s45 horizon rule; species field `:27-34,160` is our version of type channels (profile table rows, `generate/shaders.ts` SP_*). This is the closest analogue to NE top-type; check whether it has a separate *bottom* axis (it does not appear to).
- `procedural/settings.ts:21-24,135` has a Sky Pro horizon coverage ramp (+0.12 over 45 km from 20 km).

What to try (ordered; shape/layering/detail):
1. **Dimensional-profile subtraction** for procedural density: `density = saturate(noise - (1 - profile*coverage))` [p.29, 34] with an extra sharpening `pow(.., 0.27)` [p.105]. Replaces our remap-by-factor threshold; makes coverage fatten and raise clouds together and gives flat bases for free.
2. **Separate top-type and bottom-type tables multiplied** [p.22, 26, 28]: bake two small 2D LUTs (height x type) and multiply. We have only a species row; adding a bottom axis gives ragged vs flat undersides without more noise.
3. **Billowy->wispy switch height keyed to type** `Remap(h, type-0.1, type+0.1)` into `lerp(wispy, billowy, .)` (argument order flipped from the slide so billowy sits above, as its diagram shows) [p.99-101], replacing our fixed `procRemap4(hf, 0.2, 0.4)` (`density.wgsl.ts:221`): lets one noise stack give low-cloud wisp bottoms and tall billowy tops per cloud.
4. **Thin-cloud noise slice offset** `(1 - saturate(thickness*0.0125))*40` [p.102] so small clouds are not slices of large ones; needs per-column thickness from the weather map (we have species/coverage only).
5. **Terrain edge gradient / envelope profile** `h^2 (1-h)^1.5 * edge(0..35 m)` [p.97] for valley and hero clouds; and **Influence mask layers** to overlay authored regions on the procedural weather map [p.69, 75-78].
