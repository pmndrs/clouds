## In one paragraph

The voxel path does not store density at render resolution. It stores an 8 m **dimensional profile** (an SDF-derived 0→1 gradient from outside to core) plus a **detail type** and a **density scale**, and *up-rezzes* the profile per sample by eroding it with a 128³ four-channel noise: two wispy channels (Curly-Alligator, low/high frequency) and two billowy channels (Alligator, low/high frequency). Each pair is blended **over the profile itself** (low frequency at the outer edge, high frequency toward the core), the wispy/billowy pair is blended over the type, and within 150 m a "twice-folded" copy of the high-frequency channels adds a finer octave without another fetch. The eroded result is scaled by `pow(S,4)` and "sharpened" by an exponent below 1, then softened near the camera. Claimed result: 0.5 m effective precision from 8 m voxels, 10 ms at 960×540 worst case (vs 30+ ms for dense grid sampling).

## Slide by slide

**s75 (p.83), title "Sampling Density".** Notes: from experience, splitting the work between memory fetches and ALU in the compute shader runs faster, so the detail is solved inside the density sampler, as before. Render image98.

**s76–78 (p.84–86), the up-rez idea.**
- s76: the 2.5D model decompressed 2D NDF data into a dimensional profile and eroded it with higher-frequency noise; the question was whether that carries over to a voxel ray-march. Answer: yes.
- s77: instead of explicit density at 1 m voxels, up-rez an **8 m** voxel profile with new detail noises. This trades a memory bottleneck for instructions, as the 2.5D clouds did. Figure: a cloud in its box, labelled "Dimensional Profile, Voxel Size: 8 m" vs "Explicit Density, Voxel Size: 1 m".
- s78: **before/after pair**: the profile up-rezzed (image101) and rendered raw (image102). (Corrected 2026-10-11 by looking at the images: image101 is the detailed one.) This is the clearest single "what erosion buys" figure.

**s79 (p.87), profile from SDF.** The profile is made from the cloud's signed-distance field so there is always an outside-to-inside gradient. Figure: profile render (image103) next to a **cross-section** (image104), a soft white interior with a blurred rim several voxels wide. The SDF→profile mapping (how many metres the 0→1 ramp spans) is not given here.

**s80 (p.88), modeling NVDFs.**
- Atlas (Houdini) lets the artist author Nubis Volume Data Fields: dimensional profile, **detail type** (blend wispy→billowy) and **density scale** (lowers density *after* the noise up-rez).
- 512×512×64, BC6, 1 byte/texel, 16.777 MB (= 512·512·64 bytes; BC6H is 1 B/texel, 3 channels). Figure: the three fields as white/red/green renders stacked into one texture.

**s81 (p.89), sampler skeleton** → `n3-s081.hlsl`. Fetch the profile NVDF first; if it is zero we are not in a cloud, skip everything. Otherwise pass the modeling data to the up-rez.

**s82 (p.90–91, bonus) pseudocode** → `n3-s082.hlsl`.
- `sample_coord = (p - boundsMin) / (boundsMax - boundsMin)`; modeling fetch at `inMipLevel`.
- Two outputs: `mProfile = profile * densityScale` (cheap, used to build the light-scattering volume, covered later) and `mFull = up-rez(...)` (for density and precision lighting).
- Notes: the modeling data lives in a struct because, passed into a function, members the callee never reads cost no VGPRs (if you are careful).
- Inconsistency: s82 passes the struct; the s109 signature takes three floats. The pack's `VoxelCloudSampler.cg` resolves it with floats.

**s83–88 (p.92–97), why two detail families.** Timelapses (Sony A7iii 240 mm), watched upside down so they read as milk poured into water.
- s85: vapour expanding into cold air is pushed back; **billows** are vapour punching through weak spots in that squeeze.
- s86: invert it and you get **wisps**: scalloped shapes where surrounding air billows into evaporating vapour.
- s87: a web-like timelapse; turbulence adds extra distortion.
- s88, the rule: **density decreasing ⇒ curly layered wisps; density increasing ⇒ layered billows.** (Same as SY s24–28; already in `nubis-sources.md` §3.)

**s89 (p.98), new noises.** Figure: 2×2 grid, old vs new.
- Billows: old inverted Worley needed a lot of layering in the sampler and still looked like packed spheres. New: Houdini **Alligator** noise, which looks like layered Worley but has cloud-like lacunarity.
- Wisps: old Perlin-Worley was not wispy enough for this up-rez. New: **inverted Alligator** (web-like) **distorted by curl noise**, called **Curly-Alligator**.

**s90 (p.99), the noise texture.** 4 channels, 128³: **R = low-freq Curly-Alligator, G = high-freq Curly-Alligator, B = low-freq Alligator, A = high-freq Alligator.** Labelled "Uncompressed, 2 Bytes / Texel, 4.194 Megabytes". The size equals 128³ × 2 B, which cannot hold four 16-bit channels (that would be 16.8 MB). Either 4 bits per channel or the label is wrong. **Resolved by the lead (n3.md §7b):** the pack's noise TGAs use the full 8 bits per channel (200+ distinct values per channel per slice), so the shipped noise is RGBA8, 8.4 MB; the label is the same block reused from s22. Alligator source: SideFX HDK example `alligator_2alligator_8_c-example.html`. A noise generator is promised at the end of the talk (outside this range). Figures: the four channel tiles (image35–37, image110).

**s91 (p.100) wind** → `n3-s091.hlsl`. `p -= float3(wind.xy, 0) * voxel_cloud_animation_speed`. Horizontal only (z-up). It scrolls the detail noise like the 2.5D clouds; the profile is not moved.

**s92 (p.101) noise fetch** → `n3-s092.hlsl`.
- `mip = log2(1 + |d * cVoxelFineDetailMipMapDistanceScale|)`, `noise = tex3D(p * 0.01, mip)`, so the texture tiles every **100 m** (0.78 m per texel at mip 0).
- Notes: distance MIP is about **15% faster** than a fixed MIP with no visible change. The scale constant is not given.

**s93–96 (p.102–107), wispy composite** → `n3-s095.hlsl`.
- s93: photo of wisps. The notes say very high-frequency detail sits in the thin regions and low-frequency structure in the dense regions: the low frequencies give the high frequencies structure.
- s94: the profile already provides that outside→inside gradient (figure image117).
- s95: `wispy = lerp(noise.r, noise.g, profile)`. The diagram labels profile 0 (dark, outer) "Low Frequency Wisps" and profile 1 "High Frequency Wisps".
- s96: HF only / LF only / blended renders (image118, 119, 120): a good **noise-breakdown** triplet.
- ⚠ **Narrative vs code.** Read literally, s93 puts high frequency at the thin edges; the code and the diagram put **low** frequency at the edge (profile→0) and high toward the core. Take the code as authoritative (it matches the pack). Note that erosion only cuts where `profile < noise`, so the visible silhouette always sits in the low-profile band, where the LF channel dominates.

**s97–99 (p.108–112), billowy composite** → `n3-s098.hlsl`.
- s97 (photo, Canon KissX2 80 mm): the notes say low-frequency billows near the core and higher-frequency billows near the surface.
- s98: `billowy = lerp(noise.b*0.3, noise.a*0.3, pow(profile, 0.25))`. Notes: edges should be rounder than the core, or there would be high-frequency noise everywhere on the edges. So again LF at the edge, HF inward. ⚠ The same narrative/code tension as s93 (s97's photo description vs s98's notes and the code); the code and s98 agree.
- **Constants:**
  - The `*0.3` caps billow erosion at 0.3 of the profile range, so billows only cut the outer ~30% of the gradient. Wisps are uncapped and can cut deep.
  - `pow(P, 0.25)` reaches HF fast: P = 0.1 → 0.56, P = 0.3 → 0.74. Pure LF exists only in the outermost fringe.
- s99: HF / LF / blended renders (image122–124).

**s100–101 (p.113–116), type blend** → `n3-s100.hlsl`. `noise_composite = lerp(wispy, billowy, type)` (the variable is `detail_type` here, `inType` in s98/s109). The comment says the blend goes wispy "as the density scale decreases", but the blend factor is the type field, not the density scale. Renders: wispy only / billowy only / blended over type (image125–127).

**s102–106 (p.117–122), near-camera "high high frequency"** → `n3-s103.hlsl`.
- s102: fine from a distance, but flying close there is a dramatic lack of detail. Reuse the fetched HF channels instead of a second 3D fetch, which is expensive in the sampler.
- s103, **twice-folded noise**: map to [-1,1], fold over zero with `abs`, twice:
  - `fold2(n) = |(|2n-1|)*2-1|`, a triangle wave with two periods over n ∈ [0,1]: n = 0, 0.5, 1 → 1; n = 0.25, 0.75 → 0.
  - `hhf_wisps = 1 - fold2(g)^4` (mostly near 1, thin dips: web lines).
  - `hhf_billows = fold2(a)^2`.
  - Figure: a 1D plot of the folded signal (image129).
- s104: blend the two by type, then blend from the normal composite to the HHF composite toward the camera over **150 m**. Diagram: camera → 150 m arrow.
- s105: without/with close-up pair (image130/131). s106: fly-in video, seamless.
- **Exact blend (s109):** `noise = lerp(hhf, noise, ValueRemap(d, 50, 150, 0.9, 1.0))`. ValueRemap clamps (pack), so even at d < 50 m the HHF weight is only **0.1**. The HHF perturbs the erosion threshold by at most ±0.1. The visible near-camera change comes as much from the softening step below as from the HHF noise.

**s107 (p.123), erode, scale, sharpen** → `n3-s107.hlsl`.
- `ValueErosion(P, noise)` (notes: the 2.5D remap erosion). Pack definition: `saturate((P - n) / (1 - n))`.
- Then multiply by density scale, then `pow(rho, lerp(0.3, 0.6, max(EPS, pow(sat(S),4))))`.
- Notes: sharpen more where density is low to bring out definition.
- ⚠ s107 multiplies by **linear** `inDensityScale`; s109 (and the pack) multiply by `pow(sat(S),4)`. Use s109.
- Build renders image136→135→134→133. Order inferred from the look: soft raw profile → eroded with a wispy base fringe → density scale trims the fringe → sharpened final.

**s108 (p.124), summary.**
- Seamless detail over distance; no memory bottleneck; **0.5 m precision from 8 m**; balanced memory vs ALU.
- Cost **10 ms at 960×540** worst case, seen from the ground. Dense-grid sampling cost **30+ ms**. The notes say this is not AAA real-time yet, and the rest of the talk is optimisation.

**s109 (p.125, bonus), full HLSL up-rez** → `n3-s109.hlsl`. Verbatim match with the pack's `GetUprezzedVoxelCloudDensity`, except the wind speed name (`voxel_cloud_animation_speed` vs pack `low_cloud_animation_speed`).

Extra steps not shown on s91–107:
- `powered_density_scale = pow(sat(S), 4)` is used for both the multiply and the exponent.
- Near camera: `f = sat((d-50)/100)`, `rho = pow(rho, lerp(0.5,1,f)) * lerp(0.666,1,f)`. The comment calls the result "softened edges": at d ≤ 50 m it lifts thin density (sqrt) but caps the peak at 2/3.
- The HHF comment mentions only the billowy noise, but the code folds both `g` (wispy) and `a` (billowy).

## Formulas and constants (all s109 unless noted)

| Item | Value |
| --- | --- |
| Profile voxel / NVDF | 8 m; 512×512×64; BC6 1 B/texel; channels profile, type, density scale [s77, s80] |
| Noise | 128³, R/G LF/HF Curly-Alligator, B/A LF/HF Alligator; `p*0.01` (100 m tile) [s90, s92] |
| Noise MIP | `log2(1+|d*k|)` (+ base mip in pack); k unpublished; ~15% faster [s92] |
| Wispy | `lerp(r, g, P)` [s95] |
| Billowy | `lerp(0.3b, 0.3a, P^0.25)` [s98] |
| Composite | `lerp(wispy, billowy, T)` [s98, s100] |
| HHF | `sat(lerp(1-fold2(g)^4, fold2(a)^2, T))`; weight `1 - ValueRemap(d,50,150,0.9,1)` → 0.1 at ≤50 m, 0 at ≥150 m [s103–104] |
| Erosion | `sat((P-n)/(1-n))` (pack) [s107] |
| Density scale | `S' = sat(S)^4`; `rho *= S'` (s107: linear S) |
| Sharpen | `rho = pow(rho, lerp(0.3, 0.6, max(EPS, S')))`; EPS value unpublished [s107] |
| Near soften | `f = sat((d-50)/100)`; `rho = pow(rho, lerp(0.5,1,f)) * lerp(0.666,1,f)` |
| Profile output | `P * S` (linear S) [s82] |
| Pack only | `mFull *= ValueRemap(d, 10, 120, 0.25, 1)` (see-through near camera); dome renders use `P*S` |
| Cost | 10 ms @ 960×540 worst; dense grid 30+ ms [s108] |

A derived note on the sharpen step: the exponent is below 1, so it **lifts** low densities, which hardens the silhouette rather than thinning it. Combined with the multiply, `(S^4)^e` with e ≈ 0.3 gives roughly `S^1.3` for the core, so the `^4` mostly comes back out. The real effect of a low S is a much softer exponent (0.3) on the eroded fringe.

## Contradictions with existing notes

- `nubis-sources.md` §2 says the noise is "128³ RGBA16, 4.2 MB". The deck says 2 B/texel, 4.194 MB, which does not fit RGBA16 (16.8 MB). The pack is RGBA8 (8.4 MB). Fix the note to say "4 ch, size label inconsistent; pack is RGBA8".
- `nubis-sources.md` §3 writes the HHF gate as `if d < 150`. In the deck the gate is the caller's `inHFDetails` flag; the 150 m is the comment and the ramp end. Equivalent only if the caller gates at ≥150 m (see the runtime mismatch below).
- Everything else in `nubis-sources.md` §3 matches s109 and the pack.
