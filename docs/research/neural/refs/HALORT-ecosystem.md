# HaloRT ecosystem — code, data, demos and what is NOT public

Checked 2026-11-23 with `gh api` and curl. Paper: arXiv 2611.12103 (local: `artifacts/research/papers/neural/HALORT-leonard-westermann-2026.pdf`).

## Public pieces
- **Inference repo** https://github.com/rendervous/HaloRT — Python plus GLSL headers, MIT, last push 2026-11-13. Contents: `halort/_modeling.py` (the two attention UNets and the Denoiser/DenoiserX baselines), `ndvpt_modeling.py`, GLSL feature-extraction headers (`volume_deep_profile.h`, `volume_deep_profile_no_nee.h`, `fsg_profile.h`, `pbvrt_port.h`), pretrained `state_dict`s (`halo_dir.pt` + `halo_env.pt`, `denoiser.pt`, `denoiserx.pt`, about 4.5 MB each per README), two sample clouds (ids 0 and 487, max 160 voxels), two Colab notebooks (getting started, parameter sweep), and a GitHub Pages site. The README says explicitly it contains NO training code, NO full experiment suite and NO dataset-generation pipeline. Depends on `rendervous` and `vulky` (Vulkan with CUDA interop, a Vulkan-capable NVIDIA GPU).
- **Project page** https://rendervous.github.io/HaloRT/ — abstract, comparison explorer (reference vs HaloRT vs Denoiser vs DenoiserX for 7 HDR environments), a feature slider (albedo, transmittance, direct light, environment, 4 "crossing" layers, reconstruction), video. Source in the repo `docs/` folder.
- **rendervous (rdv)** https://github.com/rendervous/rdv_project — Python, MIT, PyPI `rendervous` 0.0.4; "tensor-library agnostic differentiable engine based on megakernel compute, built on vulky". Contains the volume path tracers used for references: `PBVR`, `PBVRT` (adds transmittance channel and next-event estimation), ratio-tracking and ray-marching transmittance, majorant grids, environment samplers (in `src/rdv/domain/volumes.py`, GLSL under `src/rdv/shaders/`). So the reference path tracer is public, but the exact reference settings (4096 spp images, 22,000 instances) are in unreleased training scripts. Older https://github.com/rendervous/rdv ("Rendervous 2.0", LGPL-2.1, last push 2026-05) and https://github.com/rendervous/rendervous_project are earlier incarnations.
- **vulky** https://github.com/rendervous/vk_project (also `vulky_project`) — Python Vulkan wrapper, PyPI `vulky` 0.1.6, MIT per PyPI (GitHub shows no licence on the repo). Notebook-heavy, no README summary to speak of.
- **Standalone cloud renderer** https://github.com/rendervous/cloud_renderer — Python CLI, no licence file, renders a `.npy` density volume under a directional light and/or HDR environment with rdv's NEE volume path tracers (`PBVR_NEE`, `PBVR_ENV`); includes a Colab demo and a 1024 spp Disney-cloud example. This is the simplest route to our own reference images.
- **Dataset** https://huggingface.co/datasets/rendervous-project/compact_clouds — `clouds_500.h5`, 13.69 GB (13,690,025,951 bytes), licence MIT (dataset card), 500 clouds, `(D,H,W,1)` float per cloud, card text: "a compacted version of the cloudy dataset", cite LTW25. Full set: `rendervous-project/cloudy`, `cloudy.7z`, 29.6 GB, MIT. Environment maps: the paper uses 1000 Stable-Diffusion-synthesised HDRIs; they are not published anywhere we found (the project page explorer uses named HDRIs such as kiara_sunset, kloofendal, syferfontein, i.e. polyhaven-style).
- **WebGPU demo (important)** https://rendervous.github.io/rdv_on_the_web/ (source https://github.com/rendervous/rdv_on_the_web, no licence file). Live pages: volume transmittance, volume radiance (delta tracking + NEE path tracer in the browser), volume deep features (13 per-pixel features shown as RGB), HaloRT (dir + env UNets exported to ONNX, run in ONNX Runtime Web on WebGPU, `halort_256.onnx`/`halort_512.onnx`, 12 MB fp32 / 7.5 MB fp16; features computed by rdv megakernels exported to WGSL through glslang -> SPIR-V -> Tint, GPU work recorded and replayed to skip ORT's CPU overhead, up to 3 frames in flight), and a directional-light-only variant with a clip plane (`halort_dir_*.onnx`, 3.7-6 MB). The README says the exporters live in `src/training/export_deep_features_webgpu.py`, `export_halort_webgpu.py`, `export_halort_onnx.py`, `export_halort_dir.py` in a repo called `direct_neural_rendering`. Needs the `float32-filterable` WebGPU feature.

## Not public (as of today)
- Training code, loss, hyperparameters, the 22,000-instance training set and the exact scene sampler: not released. README of HaloRT says so; the `direct_neural_rendering` repo named in rdv_on_the_web returns 404 on rendervous and was not found under lleonart1984 either.
- The 1000 synthetic environment maps.
- `rendervous/volcraft` ("Compact Neural Volumes for Fast Reconstruction, Animation, and Rendering") exists but is an EMPTY repository (created 2026-11-10); worth re-checking later.

## Related code by the same group (for reference-image tooling and volume tooling)
- https://github.com/rendervous/cloudy_project (MIT): diffusion cloud generator/reconstructor with a Vulkan differentiable volume renderer.
- https://github.com/rendervous/vol_rec_from_images (MIT, 2024): "Image-based Reconstruction of Heterogeneous Media in the Presence of Multiple Light-Scattering" (differentiable volume reconstruction).
- https://github.com/lleonart1984/eurographics_cvae (MIT, C++): LHW21 path tracer with learned sphere-tracing.
- https://github.com/lleonart1984/cumgen: "Cumulus density volume compressed dataset generator via Implicit Neural Representations", MIT, effectively empty (3 KB).
- https://github.com/lleonart1984/rendervous (2023, Python, no licence): early rendervous.
- Author handle on GitHub is `lleonart1984` (personal) and `rendervous` (project account, "Rendervous Project").

## What this means for us
- The pretrained HaloRT weights AND ONNX exports are public and MIT, so we can run the real network in a browser today (ONNX Runtime Web on WebGPU), and the feature extractor exists as GLSL (`volume_deep_profile.h`) that has already been lowered to WGSL for the demo. We can port the 13 features to our own WGSL without re-deriving them.
- We can NOT retrain or fine-tune on our own clouds from released code; we would have to rebuild the training loop from the paper (loss, features, UNet sizes are in the paper and `_modeling.py`).
- Cost reference (paper, RTX 5090): inference 1.4 ms at 256^2, 2.9 ms at 1024^2, 10.5 ms at 2048^2 for the 8-channel-in / 1-out UNet; the headline images (Fig. 1) are 10.2 ms per frame; MRPNN was run on an RTX 3090 because it does not run on the 5090.
