# Audit and reset plan — 2026-10-08

This document supersedes the phase/gate plans (`implementation-plan.md`,
`next-milestones.md`, `implementation-work-queue.md`, `agent-orchestration.md`,
`human-review.md`). Those files are kept for history only.

## TL;DR

The code is healthy (typecheck clean, 129/129 unit tests pass), but the project
optimized for the wrong thing. Six "phases" built a platform (packaging, React
bindings, upscaler adapter, consumer checks, evidence exporters, ~60k words of
docs) around a **correctness reference integrator** that was never designed to be
realtime and never got the core Nubis renderer structure. The result: demos that
bake for seconds on every slider change, march 512 steps per pixel, have a static
noise pattern, hard-coded light colors, and live in a box.

The fix is not more gates. It is to build the realtime renderer that every
shipping implementation (Horizon, Tidewater/Sky Pro, three-geospatial, UE5) shares,
get to Horizon-level visuals first, then layer the Nubis³ voxel/SDF work and
authored VDB clouds into **the same ray loop**.

### Why the demos "bake hard" (concrete)

From `examples/lab/realism/main.ts` and `packages/three/src/volumetric/`:

- Default **512 view steps + 128 light steps** per pixel, uniformly spaced across the
  box chord (`realistic-shader.ts`, the `for(i<steps)` loop). No coarse/fine
  stepping, no empty-space skip (the occupancy mask is not even bound in realistic
  mode), no cone-proportional step growth.
- Any sun/coverage/scale change rebakes a ≤192³ optical-depth volume where **every
  voxel marches 128 steps through the full procedural density** (~900M density
  evaluations) before the next frame.
- The frame loop only renders when "dirty"; there is no wind/time animation.
- Jitter is a fixed per-pixel hash with an explicit comment refusing to use a frame
  seed because "this experiment does not rely on unimplemented history".
- Noise textures are built on the CPU in JS (`createMorphologyNoise`).
- Lighting is decoupled from the sky: `ambient=mix(vec3(.025,.04,.065),vec3(.15,.22,.32),h)`
  and `sun=vec3(6.0,5.7,5.1)` are constants; no transmittance LUT, no aerial perspective.
- Domain is a finite box with a 180 m fade at the sides, not a planetary shell.

### Root causes

1. **Platform before picture.** P4 (upscalers), P5 (React/API), P6 (packaging,
   consumer checks) were built while the core image was explicitly "provisional".
2. **Reference-first instead of realtime-first.** The "correctness reference"
   architecture (bounded volume, uniform quadrature, no history) was iterated on
   for realism instead of being replaced by the standard realtime structure.
3. **Process overhead.** Evidence JSON, GPU "checks", review gates, model-routing
   docs. 60k words of docs against ~6.5k lines of library code. Agents spent their
   budget proving correctness of things that didn't matter visually.
4. **Wrong root for quality problems.** Large effort chased shape (Houdini
   particle VDBs, ellipsoid lobes, morphology studies) when the bigger visual gaps
   were lighting, sky coupling, and sampling.
5. **Wrong Nubis³ data model.** The research notes read the Nubis³ slides
   correctly but the code bakes *final density* (r8 atlas tiles, r8 VDB volumes).
   Nubis³ stores a *shape description*: dimensional profile, detail type,
   density scale, plus a separate SDF. Density is created at runtime by eroding
   the profile with tiling noise. Baked density can't get crisp detail
   at any distance, which is why the VDB fixtures look like smooth blobs.
6. **Acceptance bar set by a brute-force reference.** `cloud-quality-bench.md`
   judged candidates against a 640-view/64-light-sample reference and a Cycles
   8-bounce render, rejected noise mips because they scored worse against it, and
   blocked performance work behind image quality. Production renderers never
   converge; they hide error with jitter, mips and temporal accumulation.
7. **Production cloudscape shader is weaker than the "realism" lab:** single HG
   lobe (g=0.45), flat ambient, no powder or multi-scatter, a sine-product detail
   term instead of Worley erosion (`cloudscape/shaders.ts:214`), 48 uniform light
   samples across the whole world box, up to 320 full-res view steps.
8. **Work left uncommitted.** 177 files were only in the working tree until
   `066768f`.

## 2. What "good" looks like — reference implementations

| Reference | Why it matters | License |
| --- | --- | --- |
| **Tidewater `src/sky/SkyProClouds.js`** (`/Users/dex/Developer/tidewater`) | Raw WebGPU/WGSL, 60 fps at 2560×1267 on M5 Pro. Same lineage as threejsskypro.com (the "solid look" demo). | **MIT**, cloud code explicitly relicensed by its author (CREDITS.md). Portable with attribution. |
| Tidewater legacy `src/sky/Clouds.js` | Has a Chebyshev distance field, lattice-snapped SDF jumps, curl-free 3-octave Worley, cirrus | MIT |
| threejsskypro.com bundle | Same design as above; we have notes in `research/skypro-demo-reference.md` | Commercial: **reference only, do not copy** |
| Takram three-geospatial clouds | Shadow maps, Beer shadow, aerial perspective, temporal upscale | MIT |
| Schneider: HZD 2015/2017, Nubis Evolved 2022, Nubis³ 2023 | The design we're targeting | Papers |
| Hillaire 2016/2020 | Energy-conserving integration, MS octaves, sky LUTs | Papers |

The realtime structure all of them share (Tidewater numbers):

- Shape + detail noise and blue noise **loaded or GPU-baked once**.
- Weather map (1024²) + max-reduced 64² "bounds" grid for empty-space skipping,
  regenerated only when weather changes.
- **Trace 1 of every 16 pixels per frame** (4×4 lattice) at half res, with blue-noise
  + golden-ratio temporal jitter.
- Adaptive march: coarse 4× steps on a cheap density, step back and refine on hit,
  drop back to coarse after 4 empty steps; step size ∝ pixel cone; stop at T < 0.003.
- Light: 6 cone taps growing 1.7× per tap to ~2.5 km with per-tap mip LOD; reuse
  light result across ~3 view steps; cheap light once opacity > 0.5.
- Energy: dual-lobe HG (0.8 fwd / 0.2 back) with 3 octaves halving g;
  powder faded toward the sun; ambient from sky-view LUT zenith/horizon with two
  upward visibility probes + ground bounce; sun from the transmittance LUT.
- Resolve: depth- and alpha-weighted upsample, Catmull-Rom history, neighborhood
  clamp, wind-compensated reprojection; history reset on cuts/sun/coverage.
- Amortized side products: 256² cloud shadow map (¼ rows/frame), sky panorama
  (1/16 texels/frame).

None of this is exotic. We have almost none of it.

## 3. Target architecture

**One ray loop, many density sources, everything else amortized.**

```
 init (GPU compute, < 100 ms)          per weather change            per frame
 ┌──────────────────────────┐   ┌──────────────────────────┐   ┌───────────────────────────────┐
 │ shape noise 128³ PW+W    │   │ weather map (cov/type/   │   │ trace 1/16 px @ half res      │
 │ detail noise 32³ Worley  │   │   density) 512–1024²     │   │   ├ skip: bounds grid / SDF   │
 │ curl noise 128²          │   │ bounds grid (max-reduce) │   │   ├ coarse → fine adaptive    │
 │ blue noise (STBN)        │   │ voxel envelope + SDF     │   │   ├ light: 6 cone taps / vol  │
 │ sky LUTs (@pmndrs/sky)   │   │   (Nubis³ NVDF-like)     │   │   └ out: L, T, mean depth     │
 └──────────────────────────┘   │ authored brick atlas     │   │ temporal resolve → full res   │
                                └──────────────────────────┘   │ compose + aerial perspective  │
                                                               │ shadow map (amortized ¼/frame)│
                                                               └───────────────────────────────┘
```

Density at a point = **envelope × height profile − detail erosion**, where the
envelope comes from any of:

1. **Procedural layer** (HZD): weather coverage × cloud-type height gradient ×
   Perlin-Worley shape on a planetary shell.
2. **Voxel envelope** (Nubis³): low-res voxel grid with channels
   *dimensional profile / detail type / density scale* plus an **SDF channel** for
   large safe steps. Generated on GPU from weather (streams around the camera) —
   this is what lets you fly *into* clouds and get storms/anvils.
3. **Authored instances** (Sea of Thieves): VDB/mesh → bricked envelope + SDF +
   mips, placed with full TRS. Gets the same world-space detail erosion as
   everything else, so artist shapes look like clouds, not smoke sims.

All three are summed inside the same march, so transmittance, shadows, lighting,
history and aerial perspective are shared. The VDB work becomes a source of
envelopes, not a separate renderer.

### The Nubis³ field and sampler (from the 2023 slides; local copy in `artifacts/research/nubis/`)

- **NVDF:** 512×512×64 BC6, about 16.8 MB, holding three channels: dimensional
  profile (edge → core gradient), detail type (wispy ↔ billowy) and density
  scale (p.85). A separate BC1 SDF sits beside it, about 0.5 B/texel over a range
  of −256 m to 4096 m (p.157, p.160).
- **Density at runtime** (p.67, p.96–118):
  - noise mip = `log2(1 + dist·k)`
  - the noise composite blends wispy → billowy by detail type
  - `pow(profile, 0.25)` drives billow frequency
  - the profile is eroded by the noise, then × density scale
  - finally `pow(d, lerp(0.3, 0.6, …))`, which also thins density near the
    camera to hide undersampling
- **Stepping** (p.163): `step = max(sdf, max(1, sqrt(dist)·0.08)) + jitter`.
  Jitter is animated within 250 m and static beyond. Full samples are taken
  only where sdf < 0.
- **Lighting:**
  - multiple scattering: `ms = profile · exp(-sunDensity · remap(…))` (p.136)
  - ambient: `pow(1 − profile, 0.5) · exp(−ambientDensity)` (p.144)
  - inner glow for lightning (p.147)
  - voxel light grid of summed density: 0.1–0.2 ms every 8 frames, 40% faster,
    longer shadows (p.151)
- **Budget** (p.166–168, p.174): 10–12 ms → 2.2–4 ms from voxel lighting plus
  SDF stepping. View is traced at 960×540 or 480×270.
- **Authoring** (p.70): Houdini takes voxels, point clouds, meshes and 2.5D maps,
  then applies cutouts, erosion and squashing to produce the NVDF.

One field serves both near volumes and the horizon. That removes most of the
separate distance-coverage/LOD machinery in `decisions/distance-coverage.md`.

Implementation stays raw WGSL compute through the existing shared-device interop
(`gpu/`), composited into three's WebGPURenderer. TSL is not on the critical path.

## 4. Plan

Each milestone ends with: one flagship demo page running a continuous animation
loop, an always-on GPU timing HUD per pass, and side-by-side captures at 4 fixed
cameras (ground, horizon, above-layer, low sun) against Tidewater. Commit at every
working step. No evidence JSON, no review gates beyond "does it look right at
frame rate".

### M0 — Reset (1–2 days)

- Move the old labs (`clouds`, `cloudscape`, `realism`, `*-study`, `*-bench`) under
  `examples/legacy/`; keep them building.
- Archive the gate/evidence docs to `docs/archive/`; keep research notes.
- New `examples/sky/` flagship page: three WebGPURenderer, @pmndrs/sky atmosphere,
  ground plane, free-fly + orbit camera, time-of-day, wind, GPU timing HUD.
- Golden captures from Tidewater at the 4 cameras (same sun, FOV, exposure).

### M1 — Horizon-parity realtime clouds (1–2 weeks) ← the important one

Port/adapt the Tidewater/Sky Pro structure (MIT, attribute in `docs/attribution.md`),
then extend toward Schneider's model:

1. GPU noise bake: 128³ Perlin-Worley + Worley fBm shape, 32³ Worley detail, 128²
   curl, all with mips. Ship STBN blue noise as a small asset.
2. Weather compute: coverage, cloud type, density (R/G/B), scrolled by wind; bounds grid.
3. Density: shell (planet curvature), cloud-type height gradients, coverage remap,
   curl-distorted detail erosion with height-dependent strength (wispy bottoms,
   billowy tops), cheap/full density split.
4. March: bounds-grid skip, coarse/fine adaptive, cone-scaled steps, early exit.
5. Lighting: 6-tap cone light march with mips, Beer + powder, dual HG + 3 MS
   octaves, sun/ambient from sky LUTs, height-based ambient occlusion, ground bounce.
6. 4×4 lattice trace at half res + temporal resolve (depth/alpha-weighted, clamp,
   wind-compensated reprojection). Mean-depth output.
7. Compose with aerial perspective; amortized cloud shadow map onto the ground.

**Done when:** visually comparable to Tidewater at the 4 cameras; clouds ≤ 3 ms GPU at
1440p on Apple Silicon; moving the sun or coverage slider never stalls a frame;
clouds drift with wind continuously.

### M2 — Nubis³ voxel cloudscapes (2–3 weeks)

1. GPU-generated voxel envelope around the camera (toroidal, streamed in chunks)
   with channels profile / detail type / density scale, derived from weather.
2. SDF via compute (jump flood or separable Chebyshev, as in Tidewater legacy)
   with lattice-snapped jumps for coherent stepping.
3. March uses SDF outside clouds, Nubis step schedule inside; fly-through with no
   camera clamp.
4. Cloud types beyond cumulus: stratocumulus decks, towering cumulus,
   cumulonimbus with anvil (envelope-driven).
5. Precomputed light: amortized low-res sun-transmittance + ambient volume over
   the envelope (replaces the old per-change 900M-sample bake with a per-frame
   slice update).

**Done when:** a 40 s ground → through-cloud → above-layer flight at frame rate
with no popping or stepping artefacts, and a storm cell you can fly around.

### M3 — Authored clouds in the same loop (1–2 weeks)

1. **Convert VDB → NVDF channels, not density.**
   - Profile comes from the smoothed, normalized density, or from distance to
     the iso-surface.
   - Detail type is painted, or comes from a VDB attribute, or a default.
   - Density scale comes from the source.
   - The SDF is generated from the same data.

   This is what makes an artist shape erode like a cloud instead of rendering
   as smooth smoke. Store it as CLDA v2:
   - bricked (8³ + apron) sparse payload with a page table
   - mips
   - full affine transform
   - optional compression

   Converter work: extend the Houdini bridge (fast `voxelRangeAsFloat`), drop
   the per-voxel pyopenvdb reads, and prefilter when downsampling.
2. Runtime brick atlas shared by all instances; instance list with TRS + asset id;
   cell→instance grid (reuse `cells`/`world-traversal`).
3. Instances add their envelope into the shared march; world-space detail erosion
   on top (Sea of Thieves). Per-instance controls: density, erosion amount, detail type.
4. Drag-and-drop a `.clda` into the flagship demo; place/scale/rotate it in the sky.
5. Later: browser-side NanoVDB/PicoVDB reader, mesh → cloud authoring in-browser.

**Done when:** an artist VDB placed among procedural clouds is indistinguishable in
lighting/shadowing from its neighbours, and 10+ instances cost < 1 ms extra.

### M4 — Beyond Horizon

Pick by visual payoff after M1–M3:

- Better multiple scattering (Hillaire-style MS LUT for clouds, or a small
  precomputed/learned transfer table indexed by optical depth + phase angle).
- Cirrus/altostratus via the existing 2D layer, lit from the same sky.
- Crepuscular rays from the cloud shadow map; lightning in storm cells.
- Temporal upscaler hookup (existing FSR adapter) for full-frame reconstruction.
- Weather evolution (time-varying weather fields, growth/dissipation).

### M5 — Library and React

Rebind `@clouds/three` and `@clouds/react` to the new renderer, define the public
API from what the flagship demo actually needed, then publish.

## 5. Working rules for agents going forward

- **Image first.** No platform/API/packaging work before M1 is done.
- **Frame rate is a hard constraint, not a preset.** Anything that stalls a frame
  is a bug.
- **Always animated.** The demo loop renders every frame with wind and history.
- **Commit every working step** to a branch; never leave work only in the tree.
- **Docs budget:** one status section in this file per milestone, plus research
  notes. No evidence JSON, review-gate docs, or orchestration docs.
- **Comparison over self-reported checks:** side-by-side captures vs Tidewater
  and the Nubis slides are the acceptance test. Never use a brute-force or
  path-traced render as the quality gate. Quality and budget are designed
  together.
- Tidewater code may be ported with attribution; the threejsskypro.com bundle
  may not be copied.
